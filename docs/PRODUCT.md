# HAL100 产品定义

本文维护稳定的产品定位与范围；版本、已完成迭代、schema、RPC和工具数量等易变事实以
[当前开发状态](CURRENT_STATE.md)为准。

## 1. 产品愿景

HAL100 是本地 AI 模型与推理环境的统一控制中心。它让用户在一个标准化桌面界面中完成模型下载、导入、启动、停止、切换和后端连接，并通过本地 API 网关向 AI Agent 软件提供统一访问入口和精确用量统计。

HAL100 不是完整聊天客户端。内置对话仅用于验证模型是否可用、工具调用是否正常以及配置是否正确。

## 2. 核心价值

1. 统一管理本地模型、托管引擎和外部推理后端。
2. 为 OpenCode及其他兼容客户端提供稳定的本地 API 地址。
3. 从推理响应中采集准确 Token，并按客户端、模型、后端和时间归类。
4. 通过受控的 HAL100 Agent帮助用户配置本地推理环境。
5. 长期后台运行时保持低 CPU、低内存和低磁盘写入。
6. 默认本地优先，不保存提示词和模型回答，不静默调用云端。

## 3. 当前平台与开发范围

- 运行平台：Apple Silicon Mac。
- Intel Mac：永不支持。
- Windows：首批不开发；未来仅考虑 Windows 10/11。
- Linux：不在当前产品范围内。
- 界面语言：首版仅中文。
- 许可证：MIT。
- 当前阶段：开发初期，仅内部开发测试。
- 发布边界：不考虑签名、公证、应用商店、安装包、自动更新、正式升级和正式发售；这些事项不属于当前缺陷或默认下一阶段任务。
- 迭代方式：始终维护同一个可运行开发版，不按迭代制作安装包。
- macOS最低工程基线：macOS 13 Ventura。

## 4. 首版功能范围

### 4.1 模型管理

- 下载 GGUF模型。
- 同时支持 Hugging Face和ModelScope。
- 用户可选择默认下载源。
- 断点续传、空间检查和哈希校验。
- 导入本地 GGUF文件。
- 维护 HAL100托管模型与外部模型的不同所有权。
- HAL100下载的模型删除时优先移入废纸篓。
- 外部导入模型默认只移除索引，不删除源文件。

### 4.2 推理后端

- 首版完整托管 `llama.cpp`。
- 连接外部 Ollama、vLLM、llama.cpp Server。
- 连接本机、Docker、虚拟机、局域网和自定义兼容 API。
- 默认一个主要用户模型。
- 支持多个外部后端和按模型别名路由。
- 有活动请求时安全排空后切换；强制切换必须确认。

### 4.3 本地 API网关

- 默认监听 `127.0.0.1:10100`，实际端口需支持冲突检测和配置。
- 支持 OpenAI Chat Completions。
- 支持 OpenAI Responses。
- 支持 Anthropic Messages。
- 支持模型列表、流式响应、工具调用、请求取消和 Usage。
- 为不同客户端生成不同本地凭据，用于访问控制和用量归属。

### 4.4 软件接入

- 专门适配 OpenCode、Pi Coding Agent、OpenClaw和Hermes Agent。
- 每个客户端拥有独立检测、配置格式、Gateway凭据、Usage身份和可逆断开流程。
- 配置必须经过语义预览、原生确认、现实快照复验、备份或安全回滚、原子写入和写后验证。
- 只管理 HAL100拥有的配置片段，不覆盖用户已有Provider、默认模型、会话、扩展或其他设置。
- OpenCode项目配置只诊断不擅自修改；Pi、OpenClaw和Hermes分别遵循其专用配置与所有权边界。
- 通用OpenAI兼容与Anthropic Messages客户端可获得独立、只显示一次的本地Key。

### 4.5 Token与性能统计

- 按客户端、模型、后端、协议和时间统计。
- 记录输入（缓存命中）、输入（缓存未命中）和输出 Token（以后端精确Usage为准）。
- 记录首字延迟、总延迟、状态和错误类别。
- 后端未返回Usage时明确标记`unavailable`，当前版本不执行Token估算。
- 年、月、周、天范围以及客户端、模型、后端和状态筛选统一驱动摘要、趋势、构成和明细。
- 请求明细默认保留90天。
- 日/小时图表从同一Usage事实表按范围聚合，不维护第二套持久化事实源。
- 用户可选择30天、90天、180天、365天或永久保留，并在预览与原生确认后清除过期数据。
- 默认不保存提示词和回答。

### 4.6 HAL100 Agent

- 本地小模型是默认 Agent。
- Agent编排采用 Pi项目的 `pi-agent-core`，并通过 `pi-ai`连接 HAL100 Gateway。
- Pi运行在按需 Agent Kernel Sidecar中；不嵌入完整 Coding Agent、TUI或内置编程工具。
- Agent仅负责 HAL100、本地模型、推理引擎和运行环境。
- 不作为通用聊天助手。
- Agent通过结构化白名单工具工作，不直接获得任意 Shell权限。
- Pi不自动加载用户或项目扩展、Skills、Prompt Templates、`.pi`目录和 `AGENTS.md`。
- Rust Core负责所有工具复验、权限、确认、执行和审计。
- 安装、卸载和删除操作必须预览并由用户确认。
- Kernel Sidecar按任务运行并在完成后立即退出；本地 Agent模型运行时在最后一次任务后空闲两分钟卸载。
- 当前内部开发基线使用Qwen3.5-2B Q4_K_M；固定硬件、运行目录、计划和取消场景已经完成真实工具调用验收，后续替换模型仍须通过同一基准。
- 当前RPC v12固定注册19项工具；确定性入口无法解析时，Pi可在确定性采样、128 Token上限的零工具调用中提交有界意图并由Rust双路裁决。可信任务的工具集合只由Rust工作流派生；澄清/拒绝固定回答，含工具未解析时故障关闭，只有零工具解释保留兼容。任务按相关指令和直接工具依赖装配上下文，最终计划成功后固定收口；回合、Usage和重复工具结果指标由Rust复核且不保存用户内容。Agent可读取脱敏系统、运行时、诊断、四类外部Agent、运维历史和短时健康状态，并能为当前活动模型生成一次性安全停止计划；不返回本地路径或凭据。
- 本地Agent保留16K基线，并在16 GiB及以上Apple Silicon设备使用已实测32K标准档；档位只由
  Rust选择并显示在技术详情中，Pi和用户文本不能扩大容量，64K尚未开放。
- Agent可为本地模型启动/安全切换、停止当前活动模型、模型移除、公开GGUF搜索/下载、llama.cpp安装/卸载、四类外部Agent配置/断开，以及Pi Coding Agent私有安装/移除生成5分钟有效的一次性计划；计划本身不执行，必须由Rust原生确认并重新校验。
- Rust任务状态机串联检查、规划、等待确认、执行、复验和终态。公开检查点只包含有界任务类别
  与阶段，不保存用户内容、具体目标或授权ID；只有同一进程中仍有效的精确计划可以继续确认，
  应用重启不恢复任务或执行权限。
- 活动任务可以取消；取消必须终止Sidecar、释放临时凭据并停止独立Agent模型。
- 模型移除按所有权处理：托管文件只移入系统废纸篓，外部模型只移除索引，内置Agent模型禁止移除。失败下载分片清理、外部模型源文件删除、任意命令和强制切换当前没有Agent工具。

### 4.7 云端增强 Agent

- 仅使用用户自带 API Key（BYOK）。
- 同时支持 OpenAI兼容和 Anthropic兼容 API。
- 默认本地模式。
- 云端只能由用户单次或按会话主动开启，不能静默回退。
- 发送前脱敏并展示预览。
- Agent Sidecar通过 HAL100 Gateway调用云端模型，不直接获得用户 API Key。
- 云端模型提出工具调用，但仍受本地权限、确认和执行器约束。
- 云端 Agent Token单独统计。

当前开发版已完成“单次云端增强”和“当前会话使用云端”两条闭环。用户从已有推理后端中选择已配置的OpenAI或Anthropic兼容服务并填写模型ID；单次模式先预览本次发送，再原生确认本次调用；会话模式先预览后续任务的数据范围，再由macOS原生窗口确认。会话授权只保存在当前Rust进程内存，不保存聊天历史，明确退出或应用重启后恢复本地Qwen默认。后端删除、失载、认证或请求失败时持续显示故障状态并直接失败，不回退本地。

### 4.8 标准界面

- 首页：真实就绪度、一个优先事项和推荐下一步。
- 模型与运行：模型库、运行时、推理服务和模型测试的稳定子路由。
- 软件接入：四类专用外部Agent、内置Runtime边界和通用客户端。
- Agent：Provider选择、上下文任务、完整任务库、回答与受控计划。
- 活动：统一范围用量与最近受控操作记录。
- 设置：基础偏好、外观、数据保留和版本信息，独立位于侧栏底部。
- 系统托盘：关闭主窗口后继续运行并可恢复窗口。

产品不设置简单模式和高级模式，所有用户使用统一的信息架构和交互规则。

界面以 Claude Desktop的安静、温暖和克制工作台体验为参考，但使用 HAL100自有暗红品牌色、系统管理信息架构、组件和文案。详细规范见 [UI/UX设计规范](UI_UX_SPEC.md) 与 [低保真线框图](UI_WIREFRAMES.md)。

## 5. 后台生命周期

- 首次启动询问是否随系统登录启动，默认关闭。
- 登录启动时只启动后台核心、托盘和网关，不打开窗口、不加载模型。
- 关闭主窗口时隐藏并复用主 WebView，暂停全部前端周期活动，保留 Rust Core、托盘和网关。
- 托管用户模型当前由用户显式启动、切换和停止，不启用15分钟自动卸载。
- 外部后端不由 HAL100自动停止。
- 休眠唤醒后检查端口、数据库和后端，但不主动加载大模型。
- 明确退出 HAL100时停止接收请求、安全排空并停止托管子进程。

## 6. 非目标

- 完整聊天客户端。
- 训练、微调和模型量化工作台。
- 云端模型代付或 HAL100官方云服务。
- 系统级 HTTPS流量拦截。
- 在 Agent未经过权限系统时执行任意系统命令。
- Intel Mac、Linux或首批 Windows版本。
- 首版团队同步、账号系统、远程控制和多机分布式推理。
- 当前开发阶段的签名、公证、应用商店、安装包、自动更新、正式升级和正式发布流水线。
