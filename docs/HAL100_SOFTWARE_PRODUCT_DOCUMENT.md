## 1. 产品概述

### 1.1 产品定义

HAL100是一款本地 AI模型与推理环境管理软件。它在用户电脑上长期后台运行，统一管理模型文件、推理引擎、外部后端、AI Agent软件接入、Token用量统计以及本地推理环境配置。

HAL100同时承担三个核心角色：

1. **本地 AI控制中心**：下载、导入、启动、停止、切换和监测本地模型与推理后端。
2. **本地推理网关**：作为 OpenCode等 AI Agent软件与 vLLM、llama.cpp、Ollama等推理后端之间的中转站。
3. **本地配置 Agent**：通过内置小模型和受控工具帮助用户检测硬件、安装或卸载托管引擎、管理模型和排查配置问题。

HAL100不是完整聊天客户端。软件内置的对话页面只用于测试模型连接、模型回答、流式响应和工具调用，不发展为通用聊天产品。

### 1.2 产品愿景

用户只需要记住 HAL100提供的一个稳定本地 API地址，即可让不同 AI Agent软件使用本地或局域网推理后端。用户可以在 HAL100中切换模型和后端，而无需反复修改每个客户端；同时可以准确了解不同客户端、模型和时间段产生的 Token和性能数据。

### 1.3 核心价值

- 降低本地 AI模型和引擎的安装、配置与维护门槛。
- 用统一入口屏蔽不同推理后端的协议和生命周期差异。
- 不读取 Agent软件内部数据库即可按客户端统计 Token。
- 默认本地优先，不保存提示词和回答，不静默调用云端。
- 通过受控 Agent提供自然语言配置能力，同时避免模型直接控制操作系统。
- 以低 CPU、低内存、低磁盘写入方式长期运行在后台。

## 2. 产品目标与成功标准

### 2.1 首版产品目标

1. 在 Apple Silicon Mac上稳定运行 HAL100后台核心和本地网关。
2. 完整托管一个可用的 llama.cpp推理引擎。
3. 支持下载或导入 GGUF模型并完成本地推理。
4. 让 OpenCode、Pi Coding Agent、OpenClaw和Hermes Agent通过专用适配器使用HAL100模型。
5. 提供通用 OpenAI和 Anthropic兼容接入方式。
6. 对经过 HAL100网关的请求准确统计输入、输出和性能数据。
7. 通过本地 HAL100 Agent完成硬件检测、模型和托管引擎管理。
8. 允许用户配置云端模型 API增强 HAL100 Agent，但必须由用户主动启用。
9. 在主窗口隐藏或尚未创建、无模型的后台空闲状态达到既定性能预算。

### 2.2 功能成功标准

- 用户可以不借助命令行完成核心模型管理流程。
- OpenCode可以通过 HAL100完成模型列表查询、流式生成、工具调用和取消请求。
- 模型和后端切换不要求 OpenCode修改 HAL100 Base URL。
- 每个经过网关的请求都能归属到客户端、模型和后端。
- 后端返回Usage时必须记录精确值；无法获得时必须标记`unavailable`，不得伪造估算值。
- 安装、卸载、删除和强制切换不能绕过用户确认。
- 未主动开启云端 Agent时不能产生任何云端模型请求。

### 2.3 非功能成功标准

- 后台空闲平均 CPU目标不超过0.3%。
- 后台空闲常驻内存目标不超过80 MB。
- 本机网关转发 p95附加延迟目标不超过5 ms。
- 主 WebView关闭后隐藏复用，且不保留前端轮询、动画或周期刷新。
- Agent空闲后不保留模型运行时和模型内存。
- 1小时后台稳定性测试无持续内存、连接、句柄或子进程泄漏。

以上性能数字为工程验收目标，需要在指定测试设备和 Release构建中实测校准，不是未经验证的宣传承诺。

## 3. 产品范围与平台策略

### 3.1 macOS范围

- 首版仅支持 Apple Silicon Mac。
- 未来的 macOS版本仍然只支持 Apple Silicon。
- 永不开发 Intel Mac版本。
- macOS最低工程基线为 macOS 13 Ventura。

### 3.2 Windows范围

- 当前不开发 Windows版本。
- 软件架构、数据模型、协议和领域核心必须预留 Windows边界。
- 未来若开发 Windows版本，只需要支持 Windows 10和 Windows 11。
- 当前不得为了尚未开发的 Windows版本拖慢 Mac主线。
- macOS系统调用不得散落在领域核心中，必须通过平台接口隔离。

### 3.3 其他平台

- Linux不在当前产品范围内。
- 移动端不在产品范围内。
- Web版不在产品范围内。

### 3.4 语言与交互层级

- 首版界面只提供中文。
- 不区分简单模式和高级模式。
- 所有用户使用同一套标准化界面、状态和操作规则。
- 复杂能力通过合理的信息结构、说明、默认值和确认流程呈现，而不是通过模式切换隐藏。

### 3.5 开源与许可证

- HAL100自身代码采用 MIT许可证。
- 推理引擎、模型权重和第三方依赖保留各自许可证。
- 引入第三方组件、模型或二进制时必须登记名称、来源、版本、许可证和分发要求。
- HAL100的 MIT许可证不能覆盖或替代第三方许可证。

### 3.6 当前发布策略

- 当前只供内部团队开发和测试。
- 项目处于开发初期，当前不考虑macOS签名、公证、应用商店、安装包、自动更新、正式升级或正式发售。
- 当前不建立正式发布、分发或升级流水线；这些事项不属于当前缺陷、完成条件或默认下一阶段任务。
- 软件以开发版连续迭代。
- 不在完成一个迭代后制作一个安装包。
- 版本号和Git标签只标记可复现的开发进度，不表示正式发布或兼容性承诺。

### 3.7 产品版本形态

- 当前只准备标准版。
- 标准版包含 HAL100应用、按需 Agent Kernel Sidecar和独立的本地 Agent Model Runtime。
- Agent Kernel Sidecar使用 Pi Agent Core与 Pi AI；不嵌入完整 Pi Coding Agent产品。
- HAL100 Agent模型在首次启动时下载和校验，不准备完整离线版。
- Agent Model Runtime必须独立于用户托管 llama.cpp，避免用户卸载托管引擎后 Agent无法启动。

## 4. 术语与对象定义

| 术语 | 定义 |
| --- | --- |
| HAL100 Core | 长期后台运行的 Rust核心，管理网关、状态、数据库和子进程 |
| Gateway | 监听本机回环地址、接收 AI客户端请求并转发到推理后端的本地服务 |
| Client App | OpenCode或其他通过 HAL100调用模型的软件 |
| Backend | 提供模型推理 API的服务，如托管 llama.cpp、Ollama或 vLLM |
| Managed Backend | 由 HAL100安装、启动、停止、升级和卸载的后端 |
| External Backend | 由用户或其他软件管理，HAL100只负责连接和监测的后端 |
| Managed Model | 由 HAL100下载并拥有文件管理权的模型 |
| External Model | 用户从本地文件系统导入，HAL100默认只建立索引的模型 |
| Route | 客户端请求、模型别名和实际后端模型之间的映射 |
| `hal100-active` | 指向当前活动路由的稳定虚拟模型名 |
| Usage | 某次推理请求的输入、缓存、输出 Token及性能数据 |
| HAL100 Agent | 只负责 HAL100和本地推理环境的领域受限 Agent |
| Agent Kernel Sidecar | 包含 Pi Agent Core、Pi AI和 HAL100适配层的按需编排进程 |
| Agent Model Runtime | 为 HAL100本地 Agent小模型专门提供推理的独立按需 llama.cpp进程 |
| Tool Broker | 接收 Sidecar结构化工具请求并转交 Rust Policy Engine与 Executor的受控边界 |
| BYOK | 用户提供并承担费用的云端模型 API Key |
| 精确 Usage | 由推理后端逐请求返回的 Token数据 |
| 不可计量 Usage | 后端未提供完整Usage时保留请求事实并标记`unavailable`，Token不按零或估算累计 |

## 5. 产品原则

### 5.1 本地优先

- 默认所有模型管理、推理路由和统计都在本机完成。
- 默认不上传系统信息、日志、提示词和回答。
- 云端 Agent必须由用户主动开启。

### 5.2 标准化而非模式化

- 产品只有一套标准界面。
- 同一种操作使用相同状态、术语、风险提示和确认方式。
- 所有后端通过统一能力模型呈现，不让用户直接面对实现差异。

### 5.3 确定性执行

- AI与 Pi Agent Core负责理解、解释和编排工具调用。
- 硬件检测、安装、卸载、删除、启动、停止和配置修改由确定性 Rust工具执行。
- 模型输出始终视为不可信输入。

### 5.4 低占用后台

- 只有 Rust Core、托盘、网关和必要数据库连接长期常驻。
- UI、Agent模型、用户模型、目录扫描和下载任务均按需运行。

### 5.5 用户拥有数据

- 用户可以查看用量与审计数据，并在精确预览和原生确认后清除过期记录；当前不提供导出入口。
- 外部模型和外部后端不自动获得 HAL100管理权。
- 配置修改必须可预览、备份和回滚。

## 6. 总体用户场景

### 6.1 初次使用

用户启动 HAL100，阅读本地隐私说明，选择是否随系统登录启动，选择默认模型下载源，下载 HAL100 Agent模型，执行硬件检测，然后根据建议安装托管 llama.cpp或连接外部后端。

### 6.2 OpenCode使用本地模型

用户在 HAL100中配置 OpenCode。OpenCode将请求发送到 HAL100固定地址，HAL100识别 OpenCode、选择当前路由、调用本地模型并记录 Token。用户以后切换模型时无需重新修改 OpenCode Base URL。

### 6.3 管理多个后端

用户可以同时登记托管 llama.cpp、本机 Ollama、局域网 vLLM和其他兼容服务。HAL100统一显示健康状态和能力，并通过模型别名选择实际后端。

### 6.4 使用 HAL100 Agent配置环境

用户用中文提出“检测我的电脑并安装适合的引擎”。Agent调用硬件检测工具，解释结果，提出安装计划，HAL100展示来源、版本、大小和路径，用户确认后由确定性工具执行。

### 6.5 使用云端模型辅助诊断

本地 Agent能力不足时，用户可以单次或按会话主动启用云端模型。HAL100先展示将要发送的任务、固定系统指令和所需脱敏只读工具结果范围，用户确认后发送。云端模型只能提出工具调用，不能直接操作电脑。

### 6.6 查看使用情况

用户以年、月、周、天范围，并按客户端、模型、后端或状态查看输入（缓存命中）、输入（缓存未命中）、输出Token、请求成功率和计量覆盖率。直接绕过HAL100 Gateway的请求不会进入按客户端精确统计。

## 7. 信息架构与页面规格

首版界面以安静、温暖、克制的工作台体验为参考，但不复制其他产品的商标、图标、插画、文案和专有组件。HAL100使用暖米白/暖灰表面、炭黑文字、低饱和暗红品牌色、柔和圆角、左侧导航和完整亮暗主题。当前信息精简基线已经实现；详细设计见[界面信息精简方案](UI_SIMPLIFICATION_PLAN.md)与[单文件交互原型](HAL100_UI_SIMPLIFIED_PROTOTYPE.html)。

### 7.1 首次使用与基础设置

必须包含：

1. 首次打开保留主导航并进入总览，不使用独立全屏向导；总览显示轻量设置提醒并提供进入设置的明确入口。
2. 基础必选项只有默认模型下载源和是否随系统登录启动；登录启动推荐且默认保持关闭。
3. 设备与运行建议只在添加模型、安装引擎或诊断任务中按需显示。
4. 本地推理和软件接入准备度由各自页面负责，不在设置中复制状态卡。
5. HAL100 Agent模型的下载、进度、暂停/恢复、校验和错误重试由Agent模块承载。
6. 环境检测、本地模型和软件接入属于可选准备项，其失败不得阻塞HAL100其他页面。
7. 基础设置完成后隐藏初始化进度，只保留可调整的通用、模型来源、数据保留与关于分组；设置导航用提示点表达未完成状态，不得强制重定向总览。

初始化流程必须是非线性、可退出和可恢复的。安装、卸载、删除、配置写入和强制切换仍在对应功能页进入独立预览及原生确认，不得由设置页合并授权。

### 7.2 总览

默认只显示一份用户可读状态、一项最高优先级推荐动作和必要的常用入口。尚未完成基础设置时增加一条轻量提醒与设置入口；Core、Gateway和数据库的正常状态不分别占用卡片。

模型参数、路由地址、Token明细、系统资源、软件接入技术配置和审计记录不得同时堆叠在总览，应由对应模块承载。总览在窗口可见时才允许刷新；窗口销毁后不能继续前端轮询。

### 7.3 模型库

首屏只提供HAL100托管模型和外部模型的明确标识、名称、大小、状态、主要动作与一个“添加模型”入口。来源、仓库、修订、格式、量化、路径和完整性进入模型详情；Hugging Face/ModelScope搜索、本地GGUF导入、硬件适配提示和下载任务进入添加模型抽屉。默认下载源只在设置中维护，搜索抽屉允许单次来源覆盖。
- 下载暂停、恢复、取消和失败重试。
- 启动、停止、设置为活动模型和删除/移除。
- 文件丢失、发生变化和校验失败状态。

删除规则：

- Managed Model：预览目标和大小，确认后优先移入废纸篓。
- External Model：默认只移除 HAL100索引，不删除源文件。
- 任何删除均不得以宽泛目录或未解析路径作为目标。

### 7.4 推理后端

后端分为：

1. 托管 llama.cpp。
2. 外部 llama.cpp Server。
3. 外部 Ollama。
4. 外部 vLLM。
5. 通用 OpenAI兼容后端。
6. 通用 Anthropic兼容后端。

推理服务首屏只显示当前运行状态、活动模型、主要动作与“添加推理服务”入口；自动发现、手动连接和服务类型选择进入统一抽屉。以下信息在服务详情或高级设置中按需显示：

- 管理类型：托管或外部。
- 地址和连接安全状态。
- 版本、支持协议和能力。
- 当前模型、运行状态和健康检查。
- 延迟、请求数和最近错误。
- HAL100是否有权启动、停止、升级或卸载。

外部后端可以位于本机、Docker、虚拟机或局域网。HAL100不得默认停止、升级或卸载外部后端。

### 7.5 应用接入

首屏统一显示OpenCode、Pi Coding Agent、OpenClaw、Hermes Agent和“其他客户端”五个摘要行，每个对象只保留状态和一个推荐动作。Base URL、协议、模型、版本、路径、独立Key、连接测试、配置、断开与撤销进入各自详情抽屉。每个客户端继续拥有独立用量身份；只有经过HAL100 Gateway的请求才能准确归属。

### 7.6 Token统计

整页使用统一的年、月、周、天范围以及客户端、模型、后端和状态筛选。摘要显示Token、请求数、成功率、缓存命中率和计量覆盖率；三条趋势线分别展示输入（缓存命中）、输入（缓存未命中）和输出，365天活动图只编码每日请求次数并可进入单日范围。Token构成、客户端分布和请求明细必须复用同一查询口径；无数据时显示紧凑空状态。统计页不得使用字符估算，也不得把含缓存的输入总量与缓存量当作可相加字段。

图表必须是静态、无动画、可访问的本地SVG组件，不新增持续渲染循环、ResizeObserver或后台计时器。统计数据仍只在进入页面或用户手动刷新时查询；窗口不可见时不得刷新图表。

### 7.7 HAL100 Agent

首屏显示一份就绪/需处理/运行中摘要、本地或云端Provider、最多三个上下文推荐任务、自然语言输入和分类任务库。回答与需要确认的计划优先显示；Sidecar、Model Runtime、模型名、run ID、工具名、参数摘要与轨迹进入技术详情。云端发送范围、脱敏预览和原生确认必须保留在操作现场。

Agent页面不能提供与 HAL100和本地推理无关的通用聊天定位。

### 7.8 模型测试

模型测试并入“模型与运行 → 运行”的抽屉；旧测试URL继续打开该抽屉。只包含验证所需能力：

- 使用当前活动模型。
- 输入单次测试内容。
- 显示 Token、延迟和速度。

不包含聊天历史管理、文件知识库、分享、角色市场或通用聊天产品能力。

### 7.9 设置

基础设置完成后只保留四组长期入口：通用（外观、登录启动和固定窗口行为说明）、模型来源（默认下载源）、数据保留（Token/审计周期和显式清理）以及关于（版本、平台和帮助）。Gateway、模型存储、Agent策略、云端Provider与外部软件配置由对应业务页拥有，不在设置中复制。

### 7.10 审计记录

记录：

- 安装、升级和卸载引擎。
- 下载、导入、移除和删除模型。

RPC v12还允许Pi在确定性入口未解析时进行一次零工具结构化意图提案。Sidecar只转发规范化
schema v1对象，Rust复验任务与目标并双路裁决。可信任务通过Rust固定工作流映射叶能力并闭合
前置关系，生成`requiredTools`；Pi不能提交工具。澄清/拒绝由Rust固定回答，含工具未解析时
故障关闭，只有零工具解释保留兼容。意图调用独立固定为`temperature=0`和最多128输出Token；
进程内指标只保存固定状态、计数和耗时，重启后清空。真实Qwen意图合同仍为18/18，受控接管
合同扩展后为14/14；固定样本结果不代表开放输入100%准确。

RPC v12执行链在所有设备保留16384 Token基线，并在16 GiB及以上使用已验收32768 Token标准
档；系统提示只装配本任务工具指令，后续模型回合只携带最新直接工具依赖。最终计划工具成功后
以固定未执行说明收口。完成载荷中的回合、精确Usage、峰值
上下文和重复结果数值由Rust复核；工具结果Token估算仅用于同场景效率对照。v9的18条动作路径
最小模型回合由55降至37，真实本地Qwen模型计划以2个执行回合、0次纠偏和0重复结果完成。

外部Agent的HAL100模型配置使用`managed-route-v3`，与托管llama.cpp统一为Rust选择的
16384/32768 Token上下文、1024 Token最大输出、parallel 1和reasoning off。Hermes当前至少
需要64000 Token，因此两档活动路由都会被明确阻止，不会通过虚报配置绕过。

Rust任务运行态现已接入真实生命周期和成功谓词。只读任务必须从类型化工具结果获得满足证据；
受控变更在一次性计划处暂停，只有精确原生确认能进入执行，随后分别重新读取模型活动态、模型
库、引擎、外部Agent、私有安装或修复后诊断。公开schema v3检查点只携带任务/目标类别、期望
状态、成功谓词、枚举化证据来源、三态结论、阶段序列与有界计数；它和计划都不持久化，重启后
没有可恢复任务或授权。v5生命周期合同为10/10，v6成功谓词为18/18且故障注入为6/6；首次动作
不满足最多进行1次同任务重规划，证据缺失或第二次不满足故障关闭。

当前内部开发基线已经固定为Qwen3.5-2B Q4_K_M，并完成真实中文、工具选择、状态读取、计划生成、冷启动、取消和空闲回收验收。未来替换或新增内置模型仍须通过同一结构化基准；FunctionGemma等专用工具模型只作为后续实验候选。

| FR-CLD-007 | 发送前必须脱敏并展示预览 |
| FR-CLD-008 | 云端工具调用必须经过同一 Policy Engine |
| FR-CLD-009 | 云端 Token必须单独统计 |
| FR-CLD-010 | 使用云端模式时不得同时加载本地 Agent模型 |
| FR-CLD-011 | Sidecar必须通过 HAL100 Gateway调用云端模型，不得直接获得用户 API Key |

云端 Provider配置字段：

- 用户自定义名称。
- 协议类型。
- Base URL。
- API Key。
- 模型名称。
- 超时。
- 代理设置。

### 8.9 后台生命周期

| 编号 | 需求 |
| --- | --- |
| FR-LIFE-001 | 首次启动询问是否随系统登录启动，默认关闭 |
| FR-LIFE-002 | 登录启动只启动 Core、托盘和网关 |
| FR-LIFE-003 | 登录启动不得打开主窗口或加载模型 |
| FR-LIFE-004 | 关闭主窗口必须隐藏并复用主 WebView，同时暂停全部前端周期活动 |
| FR-LIFE-005 | 托盘打开时显示既有主 WebView；尚未创建时才创建，并从 Core恢复状态 |
| FR-LIFE-006 | 休眠唤醒后检查端口、数据库和后端 |
| FR-LIFE-007 | 唤醒后不得主动加载大模型 |
| FR-LIFE-008 | 明确退出时先停止接收新请求 |
| FR-LIFE-009 | 退出时等待活动请求，超时后再询问强制退出 |
| FR-LIFE-010 | 退出时停止托管子进程，不影响外部后端 |

## 9. 关键业务流程

### 9.1 首次启动

```text
启动 HAL100
→ 显示隐私和本地优先说明
→ 询问登录启动（默认关闭）
→ 选择默认下载源
→ 下载并校验 Agent模型
→ 检测硬件
→ 推荐引擎和模型规模
→ 用户确认是否安装托管 llama.cpp
→ 可选配置 OpenCode
→ 运行健康检查/测试对话
→ 进入总览
```

### 9.2 OpenCode请求

```text
OpenCode发起请求
→ HAL100验证 OpenCode Key
→ 解析请求模型和路由
→ 活动路由不可用时故障关闭，由用户显式准备或启动模型
→ 后端健康后转发请求
→ 流式返回内容
→ 客户端取消则取消上游
→ 读取最终 Usage
→ 写入一条请求记录
→ 页面查询时按统一范围聚合日/小时数据
```

### 9.3 模型安全切换

```text
用户选择新模型
→ 检查活动请求
→ 无请求：原子切换
→ 有请求：默认等待排空
→ 用户选择强制：展示中断影响并确认
→ 停止旧托管模型
→ 启动并验证新模型
→ 原子更新 hal100-active
```

### 9.4 Agent安装托管引擎

```text
用户提出自然语言请求
→ Agent调用硬件检测
→ Rust工具返回真实配置
→ Agent解释并选择白名单安装方案
→ Policy Engine验证来源、版本、大小和路径
→ UI展示操作预览
→ 用户确认
→ Rust Executor下载、校验、安装
→ 执行健康检查
→ Agent解释结果
→ 写入审计记录
```

### 9.5 云端诊断

```text
用户主动选择云端
→ HAL100收集最小必要上下文
→ 删除 Key、用户名、路径和其他敏感信息
→ 展示发送预览
→ 用户确认
→ Sidecar通过 HAL100 Gateway调用用户配置的云端 API
→ 云端返回建议或工具调用
→ Policy Engine重新验证
→ 需要操作时再次确认
→ 本地 Executor执行
```

### 9.6 明确退出

```text
用户选择退出
→ 停止接受新请求
→ 等待活动请求完成
→ 超时则询问是否强制退出
→ 停止托管用户模型
→ 停止 Agent Kernel Sidecar和本地 Agent Model Runtime
→ 提交剩余 Usage
→ 关闭数据库和网关
→ 外部后端保持不变
```

## 10. 技术架构

### 10.1 技术栈

| 层级 | 选择 |
| --- | --- |
| 桌面容器 | Tauri 2 |
| 界面 | React + TypeScript + Vite |
| 领域与系统核心 | Rust |
| 数据库 | SQLite + WAL +显式迁移 |
| Agent编排 | Pi Agent Core + Pi AI，封装于按需 Sidecar |
| 本地 Agent推理 | 独立精简 llama.cpp Runtime |
| 用户托管推理 | 版本化 llama.cpp Server |
| 控制面 | Tauri IPC |
| Agent私有协议 | HAL100自有版本化 RPC，通过 Sidecar标准输入/输出传输 |
| 推理数据面 | 本机 HTTP + SSE/流式 |

| 未来 Windows凭据 | Windows Credential Manager |

异步运行时、HTTP框架、SQLite Rust库、前端状态库和测试库在项目骨架技术验证时锁定；选择必须满足本文件的性能、安全和可测试性要求。

### 10.2 运行拓扑

```text
OpenCode / 通用客户端
        │
        ▼
HAL100 Gateway (127.0.0.1)
        │
        ▼
Router ─────────── Usage Collector ── SQLite
  │
  ├── HAL100托管 llama.cpp
  ├── 外部 llama.cpp
  ├── 外部 Ollama
  ├── 外部 vLLM
  └── 局域网/自定义后端

React WebView ── Tauri IPC ── Rust Core
                                  │
                                  ├── Runtime Manager
                                  ├── Model Registry
                                  ├── Download Manager
                                  ├── Integration Manager
                                  └── Agent Manager / Tool Broker
                                           │
                                           ├── Agent Kernel Sidecar
                                           │     └── Pi Agent Core + Pi AI
                                           └── 本地 Agent Model Runtime

Agent Kernel Sidecar ── 临时本地凭据 ── HAL100 Gateway
                                             │
                                             ├── 本地 Agent Model Runtime
                                             └── 用户主动启用的云端 API
```

Sidecar的模型请求必须经过 HAL100 Gateway；云端 API Key由 Rust从系统凭据库读取并在 Gateway代理路径使用。Sidecar工具请求必须返回 Rust Tool Broker处理，Sidecar内不得存在直接系统执行路径。

### 10.3 进程模型

长期常驻：

- Tauri Rust Core。
- 系统托盘和单实例控制。
- 本地网关。
- SQLite连接和单写入器。
- 低频健康检查。

按需创建：

- React WebView。
- Agent Kernel Sidecar。
- 本地 Agent Model Runtime。
- 托管用户 llama.cpp。
- 下载、哈希和元数据工作任务。

首版不引入独立系统守护进程。`hal100-core` 必须保持为独立 Rust库，使未来可以提取为用户级后台服务而不重写业务逻辑。

### 10.4 Rust模块

```text
hal100-core
├── system_probe
├── model_registry
├── downloads
├── runtime_manager
├── backend_adapters
├── gateway
├── router
├── usage
├── agent
├── tools
├── policy
├── integrations
├── credentials
├── audit
└── platform
```

模块职责：

- `system_probe`：硬件、系统、进程、磁盘和能力检测。
- `model_registry`：模型元数据、文件所有权和索引。
- `downloads`：下载源、恢复、校验和安装事务。
- `runtime_manager`：托管进程状态机和健康检查。
- `backend_adapters`：后端能力和协议差异。
- `gateway`：认证、限制、流式转发和协议入口。
- `router`：模型别名、活动路由和请求排空。
- `usage`：用量标准化、聚合和保留。
- `agent`：Kernel Sidecar生命周期、私有 RPC、会话及本地/云端 Agent调度。
- `tools`：结构化白名单工具。
- `policy`：风险、参数和确认校验。
- `integrations`：OpenCode配置和回滚。
- `credentials`：Keychain和本地 Key哈希。
- `audit`：结构化日志、审计和脱敏。
- `platform`：macOS与未来 Windows接口实现。

前端不得直接访问数据库、凭据库、任意文件系统或任意 Shell。

### 10.5 Agent Kernel Sidecar

Sidecar是 HAL100维护的薄适配进程，内部使用 `@earendil-works/pi-agent-core` 和 `@earendil-works/pi-ai`。它只承担：

- Agent会话状态和多轮工具循环。
- 模型流式事件、取消和错误转换。
- HAL100系统提示与工具 Schema的模型侧注册。
- 将工具调用代理给 Rust Tool Broker。
- 通过 HAL100 Gateway调用本地或云端模型。

Sidecar明确不承担：

- 权限决策、确认令牌签发和风险降级。
- 引擎、模型、文件、进程、凭据和配置的直接操作。
- Pi Coding Tools、TUI、第三方包、扩展、Skills、Prompt Templates和上下文文件发现。
- Pi会话文件持久化和云端密钥存储。

Sidecar与 Rust之间使用 HAL100自有私有 RPC。协议至少包含版本握手、会话 ID、请求 ID、消息大小限制、超时、取消、流式事件、工具调用、工具进度、工具结果和进程退出语义。Rust领域类型不得直接暴露 Pi内部类型。

Sidecar只运行 HAL100固定代码与精确锁定的依赖，使用最小环境变量和固定工作目录，不得运行时安装包或动态加载用户代码。禁用工具约束的是模型能力；未落实平台进程沙箱时，Sidecar及其依赖仍是以当前用户身份运行的受信任代码，不能宣称具备操作系统级文件或网络隔离。

迭代1已实现 Sidecar最小启动环境和 macOS开发期拒绝测试。固定入口、工作目录、空继承环境及独立 HOME/TMPDIR属于产品启动基线；`sandbox-exec`因已被 Apple弃用，只用于当前未签名开发版的自动化验证，不构成产品承诺。独立 XPC服务或 helper app的 App Sandbox只在未来明确重新纳入签名与分发范围后评估，不属于当前路线。

### 10.6 Agent工具调用生命周期

```text
用户请求
→ Pi Agent Core调用模型
→ 模型提出 HAL100工具调用
→ Sidecar按协议发送给 Rust Tool Broker
→ Rust重新解析 Schema并检查工具白名单
→ Policy Engine检查风险、目标、所有权和确认令牌
→ Deterministic Executor执行
→ 审计并返回结构化进度/结果/错误
→ Pi Agent Core继续解释、修正或完成任务
```

Pi侧参数校验和执行前钩子只作为额外防线，不能替代 Rust校验。

### 10.7 网关请求生命周期

1. 在请求大小和连接限制内接收请求。
2. 校验本地客户端凭据。
3. 识别客户端、协议、模型别名和路由。
4. 建立请求级取消令牌和 Usage累加器。
5. 选择后端并执行最小必要协议转换。
6. 使用有界缓冲和背压流式转发。
7. 客户端断开时立即取消上游。
8. 优先读取后端最终 Usage。
9. 请求结束后向数据库写入一条事件。
10. 统一错误并保存脱敏类别。

## 11. 数据设计

### 11.1 数据存储原则

- SQLite是本地业务数据的唯一持久化事实源。
- 云端 API Key不进入 SQLite。
- 明文客户端 Key不进入 SQLite。
- 提示词和回答默认不进入 SQLite。
- 数据库必须使用显式版本迁移。
- Usage使用单写入器和 WAL短事务。
- 不允许每个流式 Token产生一次数据库写入。
- Pi自带文件会话存储默认禁用，不创建或依赖 `~/.pi`会话目录。
- 当前不持久化Agent会话或聊天历史；云端会话授权只存在于Rust进程内存。

### 11.2 当前持久化实体

- `settings`
- `models`
- `model_locations`
- `backends`
- `model_routes`
- `client_apps`
- `api_key_hashes`
- `usage_requests`
- `downloads`
- `integrations`
- `integration_resources`
- `audit_events`

当前SQLite schema为v9。日/小时Usage在查询时从`usage_requests`按统一范围聚合；Agent会话
不写SQLite，受控操作历史由脱敏`audit_events`承担。

### 11.3 请求用量记录

每次请求至少包含：

```text
request_id
client_app_id
protocol
requested_model
resolved_model
backend_id
started_at
first_token_at
completed_at
input_tokens
cached_tokens
output_tokens
total_tokens
status
error_category
usage_accuracy
```

首字延迟和总延迟由`first_token_at`、`started_at`与`completed_at`计算，不重复保存派生字段。

`usage_accuracy` 至少区分：

- `exact_backend_response`
- `exact_backend_event`
- `unavailable`

### 11.4 模型记录

至少包含：

- 模型标识和显示名。
- 格式和量化。
- 来源：Hugging Face、ModelScope或本地文件。
- 仓库、修订和文件名。
- 文件路径、大小、修改时间和校验信息。
- `managed` 或 `external` 所有权。
- 许可证信息。
- 能力和兼容性。
- 最近验证状态。

### 11.5 数据保留

- 请求明细默认90天。
- 可选30天、90天、180天、365天或永久。
- 不维护单独的每日聚合事实表；时间图表从`usage_requests`按范围聚合。
- 不运行后台清理任务；用户查看精确数量并原生确认后，才按同一截止时间显式删除过期记录。
- 当前支持查看和清除，不提供数据导出入口。
- 清除审计或大范围统计数据属于需要确认的操作。

## 12. 安全与隐私

### 12.1 信任边界

以下内容全部视为不可信：

- OpenCode和通用客户端请求。
- 模型文件和模型元数据。
- 本地或云端 Agent输出。
- Agent Kernel Sidecar消息、状态和异常。
- 外部后端响应。
- Hugging Face和ModelScope下载内容。
- OpenCode已有配置和日志。
- 用户输入的路径和后端 URL。

### 12.2 网关安全

- 默认只绑定 `127.0.0.1`，不绑定 `0.0.0.0`。
- 本地客户端使用独立凭据。
- 数据库只保存凭据哈希和显示前缀。
- 凭据比较使用恒定时间实现。
- 限制请求头、请求体、并发、空闲连接和超时。
- Authorization Header不得写入日志。
- 自定义后端 URL必须限制危险协议并防止意外访问敏感本机服务。
- 局域网后端必须明确显示传输是否加密。

### 12.3 Agent风险等级

| 等级 | 示例 | 默认规则 |
| --- | --- | --- |
| 只读 | 硬件检测、扫描、健康检查 | 可以自动执行 |
| 可逆 | 启动、停止、普通切换 | 根据当前影响提示 |
| 安装 | 下载模型、安装托管引擎 | 必须预览并确认 |
| 破坏性 | 卸载、删除、强制切换 | 必须二次确认 |
| 禁止 | 任意 Shell、任意路径删除、关闭系统安全能力 | 不提供工具 |

确认令牌必须绑定单个操作、精确参数和目标；必须短期有效、单次使用，参数变化后立即失效。

Pi Agent Core不是 HAL100安全边界。Sidecar必须满足：

- 不嵌入完整 `pi-coding-agent`，不注册任意 Shell、文件读写、进程启动或任意网络工具。
- 不扫描 `~/.pi`、项目 `.pi`、`AGENTS.md`，不加载第三方 Pi包、扩展、Skills或 Prompt Templates。
- 只使用 HAL100提供的系统提示和结构化工具代理。
- 工具代理只向 Rust Tool Broker发送请求，不直接执行系统操作。
- Rust按 HAL100 Schema重新解析并校验所有请求；Pi侧校验和确认结果不构成授权。
- HAL100只向 Sidecar传入短生命周期 Gateway凭据，不传入云端 API Key或客户端长期 Key，也不通过 RPC提供凭据读取能力。
- Sidecar不继承不必要的环境变量，工作目录固定在 HAL100受控目录。
- Sidecar只运行固定代码和精确依赖锁，禁止运行时安装包和动态加载用户代码。
- Sidecar崩溃、协议错误、超时或重启时，当前操作必须故障关闭；旧调用和旧确认全部失效。
- 私有 RPC必须有版本、会话和请求标识、大小限制、超时、取消及重复消息防护。

这些规则属于应用层控制。未采用平台进程沙箱时，Sidecar仍继承当前用户的进程权限，必须作为受信任第三方供应链代码审计；macOS和未来 Windows的权限收缩方案进入技术验证，无法实施时必须登记残余风险。

### 12.4 文件删除安全

- 删除前解析规范真实路径。
- 禁止未解析环境变量、通配符和宽泛目录。
- 禁止以用户目录、磁盘根目录或 HAL100应用数据根目录作为递归删除目标。
- Managed Model优先移入废纸篓。
- External Model默认只移除索引。
- 删除结果必须说明是否可恢复。

### 12.5 凭据安全

- 云端 API Key保存在 macOS Keychain。
- 未来 Windows使用 Credential Manager。
- 前端只看到凭据是否存在、名称和末尾提示。
- 当前没有设置导出入口；未来若新增，导出内容不得包含凭据。
- 日志、错误、崩溃报告和 Agent上下文不得包含凭据。
- OpenCode本地 Key与云端 Key完全分开。

### 12.6 云端数据边界

默认允许发送：

- 操作系统和 CPU架构。
- CPU/GPU型号。
- 总内存和可用磁盘。
- 引擎名称、版本和脱敏错误类别。
- 用户当前主动提出的问题。

默认禁止发送：

- API Key和 Authorization Header。
- 用户名、主机名和本地 IP。
- 完整本地路径。
- OpenCode等客户端的提示词和回答。
- 未经选择的日志和文件内容。

发送前必须显示脱敏预览，并由用户单次或按当前会话确认。

### 12.7 日志与审计

- 默认不记录请求和响应正文。
- 默认关闭 Debug日志。
- 日志结构化、限量、轮转和脱敏。
- 高频重复错误合并计数。
- 后台空闲时不周期性输出“正常”日志。
- 审计记录操作主体、时间、目标、动作和结果，不记录完整敏感内容。

## 13. 性能设计

### 13.1 性能预算

| 状态 | 目标 |
| --- | --- |
| 后台空闲、主窗口隐藏或尚未创建、无模型 | CPU平均≤0.3%，内存≤80 MB |
| UI打开且静止 | CPU平均≤1%，HAL100总内存≤180 MB |
| 本机网关转发 | p95附加延迟≤5 ms |
| 20个并发流式连接 | Core内存≤120 MB且无持续增长 |
| Agent空闲 | Kernel Sidecar和 Model Runtime均不存在，Agent模型内存为0 |
| 1小时空闲运行 | 无持续内存、句柄、连接和唤醒频率增长 |

### 13.2 UI生命周期

- 登录后台启动且界面尚未使用时可以不创建 WebView；创建后关闭主窗口时隐藏复用。
- React状态不是持久化事实源。
- 重新打开时显示既有 WebView并从 Rust Core和 SQLite刷新权威状态。
- UI不可见时不存在前端计时器、轮询、图表和动画。

### 13.3 网关性能规则

- 使用异步 I/O。
- 流式采用有界缓冲和背压。
- 同协议尽量直接传递响应字节。
- 不缓存完整回答。
- 取消立即传播。
- Usage解析不能阻塞转发。
- 当前不执行Token估算；缺失后端Usage时标记`unavailable`。
- 每个后端具有连接池、并发限制和超时。
- 内部通道必须有容量上限。

### 13.4 数据库性能规则

- 流式过程中只维护内存计数。
- 请求结束后写一条 Usage事件。
- 单写入器消费有界队列。
- WAL和短事务批量提交。
- 为常见筛选维度和时间范围建立索引；日/小时数据查询时聚合。
- 清理只由用户显式预览和确认触发，不在请求主路径或后台定时执行。

### 13.5 当前监测策略

| 状态 | 当前策略 |
| --- | --- |
| 后台空闲 | 不轮询 |
| 有推理请求 | 使用请求和流式事件，不另开指标轮询 |
| Usage页面可见 | 用户进入页面或显式刷新时查询，不后台轮询 |
| 下载或安装 | 只在窗口活跃且任务进行中轮询相关任务 |

不得为了读取指标每秒启动 `system_profiler`、`ioreg`、PowerShell或其他外部进程。

### 13.6 模型目录性能

- 使用 macOS文件事件增量索引。
- 文件事件防抖和去重。
- 不定时递归扫描全部模型目录。
- 外部模型通过路径、大小和修改时间识别变化。
- 只在受控下载完成或用户明确要求时计算大文件完整哈希。

### 13.7 Agent进程性能

- Pi Agent Core只存在于按需 Kernel Sidecar，不进入长期常驻 Rust Core。
- Kernel Sidecar启动时不得扫描用户目录、项目目录、Pi资源或联网刷新模型目录。
- Sidecar与 Rust私有 RPC必须使用有界队列和背压。
- 确定性入口已解析时不调用Pi意图分类；只有`Unresolved`最多增加一次零工具、128 Token模型回合。
- 确定性澄清与拒绝由Rust固定回答，不启动Kernel或Agent Model Runtime；含工具未解析时不增加回退模型回合。
- 可信结构化任务只下发叶能力及前置闭包，不与旧关键词工具集合求并集。
- 当前热模型v3合同的意图请求p95与最大延迟均约2.61秒，不包含首次模型加载或完整任务耗时。
- 云端 Agent只启动 Kernel Sidecar，不启动本地 Model Runtime。
- Sidecar按任务启动并在RPC关闭确认后立即退出；本地 Model Runtime在最后一次任务后空闲2分钟释放模型与 KV Cache。
- Sidecar退出不得遗留 Node/Bun、llama.cpp、管道、临时文件、定时器或孤儿进程。
- Sidecar冷启动、活动内存、退出时间和反复启停资源回收必须在技术验证后建立独立预算。
- Pi的活动开销不能计入或放宽后台空闲 CPU≤0.3%、内存≤80 MB目标。

## 14. 故障与恢复

### 14.1 端口冲突

- 启动时检测默认端口。
- 不得静默占用其他进程端口。
- 显示冲突进程可用信息和修改端口选项。
- OpenCode配置中的地址必须与最终网关地址保持一致。

### 14.2 后端崩溃

- 托管后端进入失败状态并保存退出原因。
- 使用有限退避，不得无限高速重启。
- 活动请求标记失败或不完整。
- 用户可查看脱敏日志和运行健康检查。
- 外部后端只报告不可用，不擅自重启。

### 14.3 客户端取消

- 立即停止向客户端写入。
- 向上游传播取消。
- 能获得后端最终 Usage时记录精确值。
- 无法获得时保留请求状态并标记`unavailable`，不估算Token。

### 14.4 下载失败

- 保留可恢复分片和任务状态。
- 用户可以重试、继续或取消。
- 最终文件未验证前不得进入 Ready状态。
- 空间不足时停止写入并提供清理建议。

### 14.5 数据库问题

- 迁移必须在事务中执行。
- 失败不得部分应用。
- 数据库忙时使用有界重试和错误提示。
- 不得因统计写入失败阻断正在进行的模型流式响应。
- 必须记录无法持久化的 Usage数量和状态。

### 14.6 睡眠与唤醒

- 唤醒后检查网关端口、数据库连接和子进程。
- 不主动加载 Agent或用户大模型。
- 第一个请求到达时按需恢复托管模型。

### 14.7 Agent Sidecar故障

- Sidecar崩溃、协议错误或超时只终止当前 Agent任务，不得终止 Rust Core或 Gateway。
- Rust关闭对应管道、取消未完成工具调用并使所有未使用确认令牌失效。
- 不得因 Sidecar不可用而回退到任意 Shell、直接系统操作或静默云端调用。
- 本地 Model Runtime在失去所属 Sidecar且无其他所有者时由 Rust回收。
- 用户可以重新启动 Agent会话；恢复前显示脱敏故障原因。

- Sidecar仍只持有短生命周期本机Gateway Key；云端Key只在Gateway内存路径使用。临时内部路由、会话Key和Sidecar目录在任务结束后回收，不改变活动后端。

- 当前会话只保存后端、模型、启用时间和固定错误码到Rust内存，不保存聊天历史、不写SQLite、不跨应用重启。后端删除、失载或认证失败时故障关闭且不回退本地；后续每项任务仍获得独立临时路由、Key和Sidecar生命周期。

- 达到门槛后准备内部开发构建。

### 迭代10：Pi受控操作与模型生命周期

- 已将HAL100 Agent私有协议升级到RPC v2，Pi Agent Core 0.84.2通过8个固定代理工具编排硬件、运行目录、OpenCode状态和五类一次性操作计划。
- 引擎安装/卸载、OpenCode配置、模型启动/切换和模型移除均由Rust生成确定性计划；Pi不取得底层计划ID，也不能直接执行。
- 模型移除按所有权处理：托管文件只移入系统废纸篓，外部文件只移除索引；执行前重新校验活动状态、路径、符号链接、文件大小和数据库快照。内置Agent模型禁止移除。
- 所有写操作继续要求Rust原生确认；模型搜索/下载、失败分片清理、任意外部文件删除和强制切换仍不开放给Agent。
- 真实Qwen验收已证明危险意图会进入Rust Tool Broker，并由Rust拒绝移除Agent自身模型；测试后文件与索引保持不变。

### 迭代11：环境诊断与受控修复

- Agent私有协议升级到RPC v3，固定工具增至10个，新增Rust按需环境诊断和单项诊断修复计划。
- 诊断覆盖托管引擎、模型库、Gateway路由/熔断和OpenCode接入；不轮询、不读取原始日志、不做完整模型哈希、不返回路径或凭据，最多返回64项发现。
- Pi只能从同一任务刚生成的报告中复制精确`reportId/findingId`选择一项带`repairKind`的问题；每次只允许一个计划，不能直接执行。
- 首批确定性修复仅包括缺失llama.cpp安装、已安装但未配置的OpenCode接入、文件仍缺失的非内置模型索引清理；完整性错误、配置冲突、后端熔断只报告。
- Rust在计划生成前重新验证现实状态，所有执行要求原生确认；成功后按需复检并把新报告返回界面。
- Agent页新增无需启动Qwen的直接诊断卡片，以及只读全面诊断、单项修复计划快捷任务；页面与后台均无诊断轮询。

### 迭代12–23：边界拆分、外部 Agent 控制面与受管生命周期

- 桌面 Agent 已拆分为协调、内核传输、工具授权、动作计划和模型 Provider 等稳定边界；规模增长由依赖方向、所有权和合同测试约束，不采用源文件行数硬上限。
- 外部 Agent 控制面已覆盖 OpenCode、Pi Coding Agent、OpenClaw 和 Hermes Agent 的隔离检测与专用配置事务，并明确区分配置接入、HAL100 私有运行时和用户独立安装。
- 该阶段将私有 RPC推进到v9和18个固定工具；全面诊断、脱敏运维历史、部署就绪检查和短时健康观测均是按需读取，不形成后台轮询或常驻监控。
- HAL100 可在原生确认后按版本化配方安装 Pi Coding Agent 0.84.2 到应用数据私有目录。配方固定顶层归档和 136 项非根 npm 依赖语义闭包，不写全局 PATH、HOME、npm prefix 或用户配置。
- HAL100 私有 Pi 可通过单独的原生确认移入系统废纸篓；执行前后验证固定路径、版本、入口和闭包，失败时恢复原目录。用户 Pi、`~/.pi` 配置、凭据和会话不属于该卸载所有权范围。
- 这些能力没有为 Sidecar 增加通用 Shell、任意文件访问、桌面自动化或 root 权限；AI 只生成受限计划，确定性执行和最终授权仍由 Rust 与用户确认掌握。

### 迭代24–30：信息架构、任务流与用量口径

### 迭代31–37：Rust任务架构、结构化意图、受控接管与证据闭环

- Rust Core以原18类配置任务建立工作流、可恢复状态和四态确定性入口，迭代43扩展为19类；Pi不能定义工具、执行参数、
  Provider、确认或授权。

## 20. 文档维护规则

- 易变实现事实必须先更新[当前开发状态](CURRENT_STATE.md)，再同步现行专题文档；不得在多个总览中维护彼此独立的当前版本清单。
- 产品设定变化时先更新本文档，再修改实现。
- 影响架构的变化必须新增 ADR并说明替代关系。
- 安全边界不得只在代码中存在，必须同步更新安全章节。
- 性能目标调整必须附带设备、构建和测试数据。
- 新增第三方组件或模型时必须更新许可证清单。
- 实现与本文档冲突时，不得以现有实现作为默认正确答案；应先确认是实现缺陷还是正式需求变更。
- ADR、旧迭代章节和基准记录保留当时事实，不因当前schema、RPC或工具数量变化而追溯改写。
