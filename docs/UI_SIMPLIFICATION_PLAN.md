# HAL100 界面信息精简完整方案

- 状态：已完成（迭代 24—28；迭代 29—30继续收口用量交互）
- 日期：2026-08-21
- 适用阶段：1.0.4 开发版及后续迭代
- 视角：产品信息架构、交互设计、前端架构、Rust 状态边界

## 1. 背景与判断

HAL100 当前已经形成模型、引擎、外部后端、软件接入、Agent、Usage、审计和设置等完整能力，但界面仍把以下四类信息放在相近层级：

1. 用户此刻要完成的任务。
2. 正常情况下无需关注的运行状态。
3. 版本、端口、路径、内部 ID 和组件名称等技术细节。
4. 只有执行配置、安装、卸载、删除或云端发送时才需要阅读的安全解释。

问题不是功能数量增长，而是信息缺少稳定分层。后续优化不删除产品能力，不以文件行数限制架构，也不降低确认和故障关闭标准；目标是让正常状态退到背景、异常和下一步动作进入前景、技术细节按需出现。

## 2. 优化目标

### 2.1 产品目标

- 一级业务导航由 8 个收敛为 5 个，设置继续位于侧栏底部。
- 用户进入任一页面后，能够在 5 秒内回答“当前状态”和“下一步动作”。
- 每个页面同一时刻最多存在一个高强调主操作。
- 默认首屏不展示不影响当前决策的路径、端口、内部 ID、依赖哈希或组件版本。
- 同一设置或状态只保留一个权威入口，不在多个页面重复维护。
- 原有能力最多通过两次明确交互可达；技术详情可允许第三次展开。

### 2.2 架构目标

- 合并用户视图，但保持模型、引擎、Gateway、外部后端、Agent、Usage 和 Audit 的领域所有权独立。
- 建立专用展示模型，不让页面直接解释复杂协议状态。
- 摘要首屏加载，低频详情按需加载。
- 统一正常、需处理、进行中、未配置四类用户状态语义。
- 保留旧路由兼容，避免导航优化破坏书签、测试和内部链接。
- 降低单页 DOM、初始查询和前端模块耦合，继续防止启动白屏。

### 2.3 明确非目标

- 不删除模型下载、导入、后端管理、Agent 计划或审计能力。
- 不合并 Rust 领域管理器或放宽 Tool Broker 权限。
- 不开放通用 Shell、任意文件读写、桌面自动化或 root Helper。
- 不在本轮引入新的云端服务、用户账户、遥测或行为追踪。
- 不为了减少文字而隐藏错误影响、云端发送范围或破坏性操作目标。

## 3. 信息分层规则

所有页面内容统一划分为三级：

| 层级 | 内容 | 默认表现 |
| --- | --- | --- |
| L1 决策层 | 当前是否可用、阻塞问题、主要结果、下一步动作 | 首屏直接显示 |
| L2 操作层 | 操作影响、可恢复性、候选项、次要设置 | 抽屉、页签或折叠区 |
| L3 技术层 | 版本、端口、路径、内部 ID、路由、哈希、原始错误码 | “技术详情”中按需显示 |

以下信息即使属于低频内容，也不能被移入难以发现的位置：

- 云端将发送的数据范围。
- 安装、卸载、删除、断开和清理的精确目标。
- 源文件是否保留、操作是否可恢复。
- 当前操作为什么被拒绝。
- 原生确认是最终授权这一事实。

### 4.1 路由规划

| 目标页面 | 新路由 | 旧路由处理 |
| --- | --- | --- |
| 首页 | `/` | 保持不变 |
| 模型 | `/workspace/models` | `/models` 重定向 |
| 运行 | `/workspace/runtime` | `/backends` 首次进入时重定向到此处 |
| 推理服务 | `/workspace/services` | 后端详情使用稳定子路由或抽屉状态 |
| 模型测试 | `/workspace/runtime/test` | `/test` 重定向并打开测试抽屉 |
| 软件接入 | `/integrations` | 保持不变 |
| Agent | `/agent` | 保持不变 |
| 用量 | `/activity/usage` | `/usage` 重定向 |
| 操作记录 | `/activity/operations` | `/audit` 重定向 |
| 设置 | `/settings` | 保持不变 |

旧路由至少保留两个开发迭代；自动化测试必须覆盖每个重定向。

## 5. 全局界面规范

### 5.1 侧栏

- 只显示：首页、模型与运行、软件接入、Agent、活动。
- 设置保留在底部。
- 移除侧栏中的外观切换，避免与设置页重复。
- 待处理问题使用一个提示点，不显示多个组件状态。
- 当前页签在“模型与运行”或“活动”内部保留，不扩展侧栏层级。

### 5.2 页面标题

- 默认只使用一个 `h1`，移除与标题同义的 eyebrow。
- 说明文字只解释用户任务，不描述实现架构。
- 刷新不再作为每页固定右上角按钮；仅在数据失败、明显过期或操作菜单中出现。
- 页面标题区最多放一个主要动作。

### 5.3 卡片与状态

- 正常状态尽量合并，不为每个内部组件创建等权卡片。
- 错误必须局部显示，不能以整页空状态覆盖其他可用内容。
- 状态词统一为：正常、需要处理、进行中、未配置。
- 更细状态只在详情中显示，例如熔断、凭据不可用、索引失效和版本不兼容。
- 同一对象默认只显示一个推荐动作；其他动作进入更多菜单或详情。

### 5.4 术语映射

| 当前技术表达 | 默认用户表达 | 技术详情保留 |
| --- | --- | --- |
| HAL100 Core | HAL100 | Core 版本和状态 |
| Gateway | 本地服务 | Gateway 地址和路由 |
| Runtime | 运行环境 | 进程和隔离策略 |
| Pi Core v0.84.2 | Agent 已就绪 | Pi 版本 |
| API Root | 服务地址 | 原始 URL |
| Model Route / Alias | 模型名称映射 | backend ID 和 resolved model |
| Keychain | 安全存储 | Keychain 实现说明 |
| Circuit Open | 暂时不可用 | 熔断计数和错误码 |
| dependency closure | 已验证安装内容 | 闭包项数和 SHA-256 |

产品名、模型名和用户主动配置的服务地址不需要刻意隐藏。

## 6. 逐页优化方案

### 6.1 首页

#### 用户任务

- 确认 HAL100 是否可用。
- 发现唯一最高优先级问题。
- 进入当前最合适的下一步。

#### 目标结构

1. 总体状态：`HAL100 运行正常`或一条可操作问题。
2. 当前工作状态：当前运行模型、已连接软件数量。
3. 一个根据现实状态生成的推荐动作。

#### 推荐动作优先级

1. 基础设置未完成 → 完成基础设置。
2. 没有可用模型 → 添加模型。
3. 推理引擎未准备 → 设置本地推理。
4. 有模型但未运行 → 启动模型。
5. 未连接软件 → 连接软件。
6. 全部就绪 → 使用 Agent 或查看活动。

#### 内容迁移

- Core、Gateway、数据库三个正常状态合并为总体状态。
- 仅当某一组件异常时显示对应名称和修复入口。
- 开发版本移至“设置 → 关于”。
- 三个固定常用入口替换为一个上下文推荐动作和两个低强调快捷入口。

### 6.2 模型与运行

该工作区使用三个稳定子路由，不把全部内容堆在一个长页面中。

#### 6.2.1 模型页签

首屏仅包含：

- 已安装模型列表。
- 模型数量与存储占用摘要。
- 主操作“添加模型”。

“添加模型”打开统一页面级抽屉：

1. 选择“在线获取”或“导入 GGUF”。
2. 在线获取时选择来源并搜索；默认继承设置，但允许本次切换。
3. 选择具体 GGUF 文件。
4. 展示大小、SHA-256、空间要求和来源后进入原生确认。

列表默认字段：名称、大小、状态、主要动作。量化、路径、仓库、修订、所有权和完整性进入详情。

以下内容不再常驻：

- 硬件详情卡。
- 默认下载源设置卡。
- 远程目录完整搜索表单。
- 模型存储绝对路径。
- “本页没有后台轮询”说明。

硬件建议只在搜索模型、空间不足或用户打开模型详情时出现。

#### 6.2.2 运行页签

首屏按状态显示一个主任务：

- 未安装引擎：设置本地推理。
- 没有模型：前往添加模型。
- 已停止：启动所选模型。
- 已运行：显示当前模型，主操作为停止或切换。

保留一个“测试当前模型”次要入口，打开测试抽屉。抽屉默认只显示输入、回答、耗时和总 Token；输入/缓存/输出 Token 进入详情。

以下内容进入技术详情：

- llama.cpp 精确版本。
- 本地监听端口。
- Gateway 接管状态。
- 强制切换和强制停止。
- 进程空闲和无轮询说明。

强制操作放入危险操作折叠区，仍必须原生确认。

#### 6.2.3 推理服务页签

- 外部后端使用紧凑行展示：名称、类型、可用状态、是否当前使用、主要动作。
- “发现本机服务”和“手动添加”合并为“添加推理服务”流程的两种方式。
- 测试连接结果显示在对应行，不生成额外常驻卡片。
- Gateway 路由和模型别名进入“高级映射”。
- 地址、认证方式、失败计数和内部 backend ID 进入详情。
- 强制切换进入更多菜单并继续要求原生确认。

### 6.3 软件接入

#### 首屏结构

- 页面级总体状态和一个“重新检测全部”低频操作。
- OpenCode、Pi Coding Agent、OpenClaw、Hermes Agent、其他客户端组成统一列表。
- 每行只显示：图标、名称、状态、一句结果、一个推荐动作。

#### 状态与动作示例

| 状态 | 摘要 | 推荐动作 |
| --- | --- | --- |
| 未检测到 | 电脑上未发现该软件 | 查看接入方式 |
| 已安装未接入 | 可以连接 HAL100 | 配置接入 |
| 已接入 | 正在使用独立身份 | 查看详情 |
| 需要处理 | 配置被外部修改或版本不兼容 | 解决问题 |
| HAL100 私有运行时存在 | 私有副本已安装 | 管理运行时 |

#### 详情抽屉

详情中包含：版本、协议、服务地址、配置格式、凭据状态、用量归属、受管资源、重新检测、断开接入，以及经过验证时才出现的受管安装/卸载入口。

“内置 Runtime 与外部 Agent 相互独立”的大卡片改为页面标题旁的“了解运行边界”。完整说明在帮助抽屉中显示。

“其他客户端”作为一个列表项进入通用 Key 创建和兼容端点管理，不再在页面底部形成大型配置区。

### 6.4 HAL100 Agent

#### 首屏结构

1. 简化状态：可用、需要准备或正在运行。
2. 本地／云端处理选择。
3. 任务输入。
4. 最多三个上下文推荐任务。
5. 一个主执行按钮。
6. 结果区域。

#### Provider 选择

- 第一层只显示“本地”和“云端”。
- 选择云端后再选择“仅本次”或“当前会话”。
- 后端与模型字段仅在云端模式出现。
- 发送范围在预览和原生确认前完整展示，不在本地模式常驻。

#### 任务模板

首屏最多三个推荐项，由当前状态决定：

- 存在错误：诊断当前问题、分析近期失败、生成单项修复计划。
- 模型未准备：硬件与模型建议、搜索模型、设置本地推理。
- 系统正常：部署检查、配置软件、查看模型状态。

全部模板进入“任务库”，按诊断、模型与运行、软件接入三个分类组织。任务库是选择器，不继续使用 13 个常驻按钮。

#### 状态与详情

默认隐藏：Pi 版本、固定模型全名、空闲退出时间、RPC 和 Rust 授权实现。统一放入“Agent 技术详情”。

环境诊断不在未请求时占据页面；当诊断完成、有问题或用户主动打开时显示。

#### 结果层级

1. 如果存在待确认计划，先显示计划目标、影响、可恢复性和确认入口。
2. 显示 Agent 回答。
3. 工具轨迹默认折叠。
4. 模型名、run ID、plan ID 和内部工具名进入技术详情。

删除空状态下固定展示的“理解任务、调用工具、生成回答”三步装饰；运行中只显示当前阶段和取消入口。

### 6.5 活动

#### 用量页签

默认显示：

- 总 Token。
- 请求数。
- 可切换年、月、周、天的 Token 趋势图，分别显示缓存命中输入、缓存未命中输入和输出 Token，用于比较计费构成随时间的变化。
- 独立全宽的过去 365 天请求活跃图，一个格子代表一个自然日；点击日期后趋势图切换为当天 24 小时分布。
- 最近客户端摘要。

输入、缓存、输出构成进入二级详情。请求明细默认折叠；无数据时显示一个空状态，不同时保留多个空卡片。

“Gateway 精确计量”“不按字符估算”等解释移入帮助说明。

#### 操作记录页签

- 默认列表只显示时间、用户可读动作、对象、成功或失败。
- 记录较少时不长期显示筛选栏；通过“筛选”按钮展开。
- target ID、event type 和白名单字段进入详情。
- 脱敏边界以详情页帮助文字说明，不在主列表下重复显示。

Usage 与 Audit 只共享页面外壳和导航，底层查询、保留策略和数据库所有权保持独立。

### 6.6 设置

#### 基础设置未完成

保留轻量引导，只要求选择下载源和登录启动偏好。用户仍可访问其他页面，不强制跳转。

#### 基础设置已完成

隐藏“初始化配置中心”、2/2 进度、环境准备度摘要和完成栏，改为普通设置分组：

- 通用：外观、登录启动。
- 模型来源：默认下载源。
- 数据保留：Token、审计保留周期和显式清理。
- 关于：版本、平台、固定窗口行为和帮助入口。

侧栏外观切换删除后，设置成为唯一长期入口。固定的“关闭窗口时隐藏”行为移到关于说明，不显示为可操作设置。

## 7. 内容处理总表

### 7.1 直接删除的常驻内容

- 页面标题上方与标题同义的 eyebrow。
- 重复的侧栏外观切换。
- 各页“没有后台轮询”的常驻说明。
- Agent 空状态三步流程。
- 设置完成后的初始化进度。
- 正常情况下重复出现的 Core、Gateway、数据库状态卡。

删除仅指不再常驻展示；必要的行为仍由实现和测试保证。

### 7.2 迁移到唯一入口

| 内容 | 唯一入口 |
| --- | --- |
| 默认下载源 | 设置 → 模型来源 |
| 外观 | 设置 → 通用 |
| 当前模型与引擎动作 | 模型与运行 → 运行 |
| 模型测试 | 运行页测试抽屉 |
| Token 与请求 | 活动 → 用量 |
| 审计 | 活动 → 操作记录 |
| 版本与平台 | 设置 → 关于 |

### 7.3 迁移到技术详情

- 端口、路径、配置格式。
- Pi、llama.cpp 和内部协议版本。
- run ID、plan ID、target ID、backend ID。
- 模型别名到后端的内部映射。
- 依赖闭包指纹、归档 SRI 和审计白名单实现。
- Keychain、SQLite 和 Rust Core 实现说明。

### 7.4 必须保留在操作现场

- 云端发送范围。
- 安装、卸载、删除和清理的目标。
- 源文件是否保留。
- 是否进入废纸篓以及失败恢复语义。
- 原生确认按钮和有效期。
- 拒绝原因与推荐解决方式。

### 8.2 展示模型

建议统一基础类型：

```ts
type UiStatus = "ready" | "attention" | "working" | "unconfigured";

interface SummaryAction {
  id: string;
  label: string;
  destination?: string;
  confirmationRequired: boolean;
}

interface StatusSummaryView {
  status: UiStatus;
  title: string;
  description?: string;
  primaryAction?: SummaryAction;
  technicalDetailAvailable: boolean;
}
```

页面不自行把十几个领域状态转换成用户文案；转换集中在 selector，并由表驱动测试覆盖。

### 8.3 查询策略

- 首次进入只请求页面摘要。
- 详情抽屉打开后才请求路径、版本、路由和审计详情。
- 隐藏的折叠区不得仅通过 CSS 隐藏后仍提前读取全部数据。
- 操作成功后只失效相关 query key。
- 不增加后台轮询；刷新仅由页面进入、用户动作或精确失效触发。
- 局部查询失败只影响对应区域。

初期可先基于现有 DTO 建立前端 selector；当同一摘要被三个以上页面复用时，再提升为 Rust/Protocol 的稳定只读摘要，避免过早扩张协议。

### 8.4 外部 Agent 注册表

统一 UI 描述符至少包含：

- 固定 integration ID。
- 显示名称和图标。
- 用户状态映射。
- 支持的动作集合。
- 详情组件入口。
- 是否具备经过验收的受管安装/卸载配方。

OpenCode、Pi、OpenClaw 和 Hermes 继续使用独立 Rust 适配器；注册表只统一呈现，不尝试统一其配置文件和生命周期实现。

### 8.5 代码分割

- 一级页面使用 `React.lazy` 或等价稳定路由分包。
- Agent、图表、远程模型搜索和后端编辑器不进入首页初始 chunk。
- Error Boundary、启动恢复和原生前端失败提示继续位于最小启动链，不参与懒加载。

## 9. Rust 与协议边界

- 现有确定性管理器、计划存储、原生确认、审计和凭据边界不因 UI 合并而改变。
- 如果新增摘要 DTO，只返回用户状态、数量、显示名称和推荐动作标识，不返回凭据、完整路径或原始日志。
- 技术详情仍通过明确的只读命令按需请求，并保持结果大小上限。
- UI 推荐动作不是授权；所有写操作继续生成 Rust 一次性计划。
- 隐藏按钮不能成为安全控制，权限仍由 Core 和 Tool Broker 决定。
- 旧命令在迁移期间保持兼容，新页面复用同一命令或通过稳定 facade 调用。

## 13. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 过度简化导致无法定位故障 | 保留按需技术详情和可导出的脱敏诊断 |
| 合并导航后单页再次膨胀 | 使用稳定子路由和页签，不把内容堆成一个长页 |
| 用户找不到低频能力 | 提供上下文动作、任务库和详情菜单 |
| 摘要状态过期 | 精确 query 失效；失败或过期时提供刷新 |
| 安全说明被隐藏 | 云端和破坏性操作在决策现场强制显示完整摘要 |
| 路由变更破坏测试和链接 | 保留重定向并建立合同测试 |
| 大规模一次性重构引入白屏 | 按四个纵向迭代迁移，每轮保持生产构建可启动 |
| 界面合并诱发领域耦合 | ViewModel 只聚合展示，领域管理器和数据库所有权不合并 |

## 14. 完成定义

只有同时满足以下条件，界面精简才算完成：

- 五入口信息架构已经稳定，旧路由仍兼容。
- 所有原有能力均有明确新位置，没有通过“暂时隐藏”遗失。
- 正常状态、异常状态和操作确认形成清晰视觉优先级。
- 技术信息默认收纳但可以被用户主动查看。
- Rust 权限、计划、所有权、凭据和审计边界没有弱化。
- 前端完成领域拆分、摘要 ViewModel、按需详情和路由分包。
- 自动化、真实 Chromium、Tauri 开发版和白屏恢复回归全部通过。
- UI/UX 规范、线框图、路线图和架构文档与最终实现同步。

## 15. 推荐决策

建议直接采用以下默认决策进入迭代24：

1. 一级业务导航固定为：首页、模型与运行、软件接入、Agent、活动。
2. 测试模型并入运行页，Usage 与 Audit 合并页面外壳。
3. 外观只在设置中维护。
4. 设置完成后不再展示初始化进度。
5. 所有技术信息遵循 L3 详情规则，但安全影响必须在操作现场显示。
6. UI 合并不改变 Rust 领域模块和确认边界。
7. 采用四轮纵向迁移，不进行一次性大重写。
