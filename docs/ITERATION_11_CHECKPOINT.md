# 迭代11检查点：环境诊断与受控修复

日期：2026-08-19

## 结论

迭代11已经完成并达到进入下一迭代的门槛。HAL100现在有一条完整的“按需诊断 → Pi解释/选择单项 → Rust生成一次性计划 → 用户原生确认 → 确定性执行 → Rust复检”闭环。验收没有执行任何安装、卸载、删除或配置写入。

## 已完成能力

- `EnvironmentDiagnostics`从Rust按需读取引擎、模型库、Gateway路由/熔断和OpenCode接入状态。
- 诊断最多返回64项脱敏发现，不读取原始日志、不执行完整模型哈希、不返回文件路径或凭据。
- Agent RPC升级到v3，Sidecar固定注册10个工具；新增环境诊断和单项诊断修复计划工具。
- Pi必须复制同一任务Rust报告中的精确`reportId/findingId`，且每次最多生成一个修复计划。
- 当前自动计划范围只有缺失llama.cpp安装、已安装但未配置的OpenCode接入、仍缺失的非内置模型索引清理。
- Rust在计划生成前重新验证现实状态；如果报告没有安全可修复项，Agent只解释结果，不强迫生成空计划或伪造ID。
- 所有计划继续复用既有确定性管理器、5分钟有效期、单次消费、原生确认和审计链。
- 执行成功后返回新的诊断报告；复检失败写固定审计码，但不会把已成功操作伪装成失败。
- Agent页新增无需启动Qwen的直接诊断卡片，以及“全面诊断环境”“生成单项修复计划”快捷任务；没有诊断轮询。

## 自动审查结论

- 性能：直接Rust诊断在真实开发数据上50次共6毫秒；闲置时没有计时器、子进程或模型驻留开销。
- 权限：Pi没有Shell、任意文件、任意进程、模型下载或强制切换工具；诊断报告本身不是授权。
- 竞态：旧报告不能直接操作状态；引擎、OpenCode和缺失模型在计划创建时再次检查。
- 故障关闭：协议版本、工具数量、必需顺序、报告关联、工具ID、单计划和动态“可修复项存在”均由Rust复验。
- 隐私：本地模式不离开电脑；用户主动选择云端Agent时，脱敏诊断工具结果可能随任务发送，但不包含路径或凭据，并受现有发送预览与原生确认范围约束。

## 验收

- `pnpm check`全量通过：Biome、双TypeScript类型检查、React/Sidecar测试、Rust格式、Clippy `-D warnings`和Workspace测试。
- Sidecar测试22项通过，桌面React测试15项通过。
- Rust诊断专项2项、Agent动态计划专项及完整Workspace测试通过。
- 本机Qwen3.5-2B真实只读诊断通过，用时17.01秒；只产生诊断工具事件，没有操作计划。
- 本机Qwen3.5-2B真实“诊断并修复”计划验收通过，用时24.64秒；只允许零或一个计划，测试后没有执行操作。

## 继续保留的限制

- 模型搜索/下载、失败分片清理、Agent模型受控重装、完整性异常修复和强制路由切换仍未开放给Agent。
- 引擎校验失败、模型变化/校验失败、OpenCode冲突或外部修改、后端熔断只报告，需要用户判断或未来专用流程。
- 正式签名、公证、自包含Sidecar和发布级平台沙箱不在当前内部开发版范围。
