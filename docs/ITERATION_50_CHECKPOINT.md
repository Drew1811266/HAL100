## 已交付能力

### 完整活动路由

- Gateway使用原子`backend + resolved model`活动路由解释`hal100-active`。
- SQLite schema v12在一个事务中持久化完整路由和旧兼容后端字段。
- 托管llama.cpp会话保存并在正常停止、强制停止或崩溃后恢复完整旧路由。

### 运行方案spec v2/schema v12

- 托管与外部方案具有显式所有权和独立数据库形状/唯一索引。
- 托管方案固定本地SHA-256、引擎版本和容量合同。
- 外部Ollama方案固定后端ID、规范API根、引擎版本、模型名和digest；容量明确为“由引擎决定”。
- v11方案向前迁移为托管所有权，未知或形状错误的数据继续由SQLite故障关闭。

### 外部Ollama受控闭环

- 本地发现和运行方案管理器共享外部引擎注册表；同一引擎的多个方案批量复用一次实时探测。
- 保存时Rust重新检查已保存后端、API根、实时版本、完整模型目录和精确digest，不信任WebView
  候选。
- 计划前已有漂移直接拒绝；计划绑定方案更新时间、所有权、后端、模型、版本和digest。
- 确认后执行前、切换后和Agent最终证据阶段再次实时复检。
- 后端切换、切换后复检或数据库提交失败时，恢复先前持久化完整路由与必要的托管运行状态。
- 并发外部方案保存通过异步互斥串行化，数据库唯一约束继续作为第二道门禁。

### 桌面运行方案

- 用户可以从可验证候选保存多个外部Ollama方案，并与托管方案统一查看、命名、切换和删除。
- 实时目录将服务不可用、后端身份变化、版本变化、模型缺失和digest变化映射为明确准备度。
- 外部身份漂移不能直接运行；“重新验证”必须经过Rust原生确认，只更新同一身份的验证快照，
  不安装、启动、拉取或切换模型。
- 激活结果显式返回所有权、活动后端、活动模型和可选托管运行时，不再把停止中的llama.cpp状态
  误当作外部方案结果。

### Pi/Agent边界

- Pi可读取托管与外部方案的ID、名称、所有权、保存后端ID、模型/引擎、可选容量和准备度。
- Pi看不到API根、digest、路径、命令、凭据或内部计划ID。
- Pi可用精确`profileId`请求Rust实时预检并生成外层一次性原生确认计划。
- Rust继续独占快照重验、外部引擎复检、原生确认、路由写入、确定性执行和最终现实证据。
- Pi没有Ollama安装、模型pull/delete、进程启停、任意URL、Shell或文件操作权限。
