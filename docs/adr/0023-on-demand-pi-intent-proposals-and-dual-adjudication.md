# ADR-0023：按需Pi意图提案与Rust双路裁决

- 状态：已接受
- 日期：2026-08-25
- 关联：ADR-0021、ADR-0022

## 背景

迭代32已经把18类HAL100配置任务、四态确定性入口和结构化意图schema放入Rust Core，但Pi尚未真正参与意图识别。若每项任务都先调用模型，会给明确模板任务增加延迟和Token；若直接采用模型返回的工具或参数，又会绕过Rust拥有的工作流、所有权和确认边界。

需要让Pi处理确定性规则不擅长的自然语言改写，同时保持快速路径、故障关闭和现行执行链稳定。

## 决策

1. Agent RPC升级到v10，增加`agent.intent.start`与`agent.intent.completed`。18项工具、调用预算和`agent.run.*`执行合同不变。
2. 只有Rust确定性路由返回`Unresolved`时才请求Pi提案。明确任务、必须澄清和必须拒绝的请求不增加模型回合。
3. 意图提案使用独立Pi Agent Core调用，不注册任何工具。模型只能输出意图schema v1允许的任务、目标、澄清、拒绝或未解析字段。
4. Sidecar先做精确JSON、字段、枚举、大小和目标格式校验，并重新构造规范对象。原始模型输出和Provider错误正文不通过RPC。
5. Rust再次验证schema版本、18类任务、目标类型、四个外部Agent ID和当前Provider，并通过`AgentTaskAdjudicator`裁决：
   - 确定性`Clarify`或`Reject`始终优先；
   - 相同任务为`Agreement`；
   - 不同任务为`Conflict`且不选择任一方；
   - 只有确定性`Unresolved`可接纳有效提案为`ProposalCandidate`；
   - 无效、失败或仍未解析的提案不产生任务。
6. 迭代33保持影子模式。被选中的提案只记录有界枚举结果，不改变`requiredTools`、写计划、原生确认、确定性执行器或用户可见回答。
7. 默认不保存提示词、模型回答、原始提案或解释文本。日志只包含裁决结果、注册任务键和有界目标ID。

## 结果

- 明确请求保留零额外模型回合的快速路径；自然语言长尾才使用Pi。
- Pi可以提升软件任务理解，但不能选择工具、权限、参数、Provider或确认状态。
- Sidecar解析错误和模型失败不会破坏旧执行路径；协议关联或形状错误仍故障关闭。
- 后续接管执行路由前，必须先用真实内置Qwen完成多次运行评测，并证明冲突、越权和未授权写操作均为零。

## 未选择方案

- 每项任务都调用Pi分类：增加明确任务延迟和Token，且没有必要。
- 让Pi直接返回工具或执行参数：跨越Rust工作流和权限边界。
- 把原始模型文本交给Rust再解析：扩大协议和日志中的不受控数据面。
- 提案失败时静默切换Provider：违反用户选择的Provider范围。
- 本轮直接切换工具执行：缺少真实模型方差与误判证据。

## 范围说明

本决策只涉及内部Agent任务协议与影子裁决，不涉及签名、公证、安装包、自动更新、正式升级或正式发布流程。
