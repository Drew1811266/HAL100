# ADR-0016：Agent RPC v5 与外部 Agent 事务能力

- 状态：已接受
- 日期：2026-08-21
- 替代范围：替代RPC v4中的OpenCode专用Agent工具；不替代各外部Agent专用适配器

## 背景

OpenCode、Pi Coding Agent、OpenClaw和Hermes Agent已经各自具备检测、一次性配置/断开计划、资源所有权、独立凭据、备份、写后验证和失败回滚。内置Pi Agent Core此前只能请求OpenCode专用状态与配置计划，无法帮助用户完成其余客户端的配置，也无法发起可逆断开。直接向Sidecar开放Shell、HOME或任意文件能力会绕过这些已经验证的适配器边界。

## 决策

1. 私有协议升级为RPC v5，注册14项固定能力。OpenCode专用工具由三项通用能力替代：外部Agent检测、配置事务计划和断开事务计划。
2. `integrationId`只能是`opencode`、`pi-coding-agent`、`openclaw`或`hermes-agent`。Rust从用户提示识别目标并绑定当前任务；Sidecar不能替换目标。
3. 通用只存在于编排层。每种客户端继续由专用适配器解释配置格式、版本、协议、受管片段和回滚行为，不建立万能配置写入器。
4. 检测结果只返回安装、版本、受管状态、协议和告警数量。路径、配置内容、告警原文、长期凭据和内部计划ID不进入模型上下文。
5. 配置与断开工具只创建Rust内存中的一次性外层计划。用户在原生窗口确认后，Rust才消费计划并调用专用适配器；断开只移除HAL100受管片段和专属凭据。
6. 本迭代不授予通用Shell、任意文件读写、Accessibility、Screen Recording或Apple Events。Pi仍不是权限主体，Rust Tool Broker仍是唯一执行权威。

## 验收与故障关闭

- Rust能力注册表、精确参数策略、Sidecar TypeBox和共享`v5-tools.json`必须保持同序同义。
- 未注册ID、额外字段、提示目标错配、先检查A再计划B、缺少前置检测、第二个写计划、过期或伪造计划全部拒绝。
- 适配器检测结果的序列化测试必须证明不存在本地路径、配置内容或告警原文。
- 取消确认、新任务、任务失败与取消必须废弃外层及内部计划；配置或断开执行失败由适配器回滚并返回固定错误码。
- 四个适配器的既有CLI端到端测试继续作为真实执行边界验收；RPC v5只负责安全编排，不复制适配器业务逻辑。

## 后果

HAL100 Agent可以帮助用户完成四类客户端的诊断、配置和精确断开，同时不获得环境级电脑控制权。以后增加外部Agent时，需要新增注册表身份、专用适配器及验收，再自动进入通用编排；不会继续增加每客户端三套Sidecar工具。需要桌面自动化的未来功能必须建立独立权限等级、作用域和系统授权设计，不能借本ADR扩大权限。
