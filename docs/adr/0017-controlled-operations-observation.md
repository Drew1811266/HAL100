# ADR-0017：受控运维观察与用户级修复边界

- 状态：已接受
- 日期：2026-08-21
- 关联：扩展ADR-0016，不改变各外部Agent专用适配器的资源所有权

## 背景

HAL100需要帮助用户部署、配置、调试、检测和监测本机AI软件。只为每个客户端提供单独的配置按钮无法支持故障归因；直接向Pi Sidecar授予Shell、HOME、日志目录或系统隐私权限，又会让模型绕过Rust确认、事务回滚和审计边界。

现有系统已经具备受限进程执行、强类型配置计划、独立凭据、备份、写后验证、回滚、环境诊断和安全审计。迭代20首先补齐观察证据和通用修复编排，而不是建立第二套执行器。

## 决策

1. 私有协议升级为RPC v6，注册15项固定能力。新增只读`inspect_operational_history`，参数只能是`{"target":"recent"}`。
2. 运维历史由Rust读取本机SQLite审计记录，最多返回24条。返回对象不含事件ID和目标ID，只允许事件类型、目标类型、时间以及通过字符集和长度复验的`errorCode`、`action`、`reason`。
3. 全面环境诊断同时调用四个专用外部Agent适配器。任何检测错误被转换为固定问题码，不把错误正文、二进制路径、配置路径或原始告警发送给模型。
4. `ConfigureExternalAgent`成为诊断修复的通用类型，精确`targetId`仍必须来自本次Rust报告中的固定注册表ID。执行继续复用对应客户端的一次性配置事务。
5. 未安装是可选信息；已安装但未配置、需要刷新或带告警才计入待处理。冲突、外部修改、版本不兼容和Blocked不能自动修复。
6. Pi只负责选择已授权能力和解释结构化证据。Rust Tool Broker仍是唯一权限主体和执行权威。

## 当前权限层级

- L0观察：系统/运行时摘要、全面诊断、单客户端状态和近期脱敏运维事件，按需执行，不需写授权。
- L1用户级事务：现有模型、引擎和外部Agent配置计划，必须原生确认、一次消费、快照复验、审计并在适用时回滚。
- L2管理员操作：尚未实现。未来必须使用独立强类型Helper和单次系统授权，不能提供root Shell。
- UI自动化：不在当前需求内，不申请辅助功能、屏幕录制或Apple Events。

## 后果

Agent可以用真实、有限、可审计的证据分析近期失败，并从同一份全面诊断为四类客户端生成确定性配置修复计划。后续部署、日志采集和显式监测应沿用“注册能力→资源作用域→风险等级→预检→确认→执行→验证→审计”的合同逐项增加，而不是放宽Sidecar进程权限或接受任意命令字符串。
