# ADR-0028：版本化内置 Agent 上下文容量

- 状态：接受
- 日期：2026-08-25

## 背景

内置Qwen3.5-2B运行时与Pi模型描述长期分别硬编码6144 Token。Pi固定保留4096 Token后，可用于
系统指令、用户任务和工具观察的空间过小；随着18类任务、工具前置关系和复验语义接入，短窗口
会提高上下文压缩、遗漏约束和重复回合的风险。只修改llama-server或Sidecar其中一侧还会产生
新的配置漂移。

## 决策

本地Agent基线提高到16384 Token，输出仍限制为768 Token、`parallel 1`、`reasoning off`，配置
任务采样温度固定为0。Pi保留4096 Token后，任务输入空间从约2048提高到12288 Token。

`contracts/agent-runtime/v1-capacity.json`作为版本化容量合同；Rust启动参数、TypeScript模型描述、
传输上限和双语言测试必须与合同一致。128 KiB工具结果仍是单次RPC安全上限，不表示每个结果都
应占满模型上下文；工具DTO继续在Rust侧按业务数量缩减，后续效率阶段还必须测量累计工具Token。

当前不直接采用32K或模型原生262K上限。更高窗口或自适应策略必须先在最低支持设备上证明内存、
延迟、取消和空闲回收没有不可接受退化。

## 结果

- 模型GGUF元数据声明原生训练上下文262144 Token，16K没有触发RoPE扩展。
- Apple M1/16 GiB真实9场景验收达到9/9；冷启动取消8毫秒、推理中取消71毫秒，空闲退出通过。
- `vmmap`物理占用556.1 MiB、峰值556.2 MiB；历史6K样本为386.4 MiB，增加约170 MiB。
- 长窗口验收暴露并修复“已明确OpenCode仍询问目标”的澄清冲突：Rust现在按原提示复验澄清是否
  必要，解释型请求在新旧路由中统一保持零工具。

## 不变边界

上下文增长不扩大工具、文件、Shell、网络、桌面、确认或执行权限，不保存提示词、回答、原始工具
结果或旧授权，也不引入后台轮询和正式分发流程。
