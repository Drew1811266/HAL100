# ADR-0029：进程内有界 Agent 澄清与同任务继续

- 状态：已采纳
- 日期：2026-08-25

## 背景

Core已经能把缺少外部Agent目标、移除所有权含糊和多个写目标识别为`Clarify`，但迭代37以前只
返回固定文字。该回答没有进入任务状态机，用户只能重写整段提示；软件也无法证明后续运行仍是
原任务、只补了一个槽位，而不是恢复旧对话或扩大授权。

## 决策

HAL100采用schema v3进程内脱敏检查点，并把澄清实现为Rust拥有的任务阶段：

- 只保留任务类别、Provider模式、公开集成候选、澄清种类、尝试计数和绝对过期时间；不保留
  提示词、回答、具体资源检查点、计划/run ID、路径、凭据或工具结果；
- 客户端只能提交枚举化选择：注册外部Agent、移除HAL100私有Pi运行时、只断开接入或取消；
- 最多2次选择、总有效期5分钟。错误种类、错误Provider、无效组合、超时、取消、新任务和重启
  均故障关闭；
- 多目标含糊移除可先选唯一目标，再选所有权；两步共享同一上限；
- 完整任务规格由Rust根据固定槽位重建。进入Pi前使用新的规范化任务说明，不恢复原提示；写操作
  仍生成新的短期计划并要求原生确认，澄清选择本身绝不等于执行授权；
- 单次云端任务在澄清后继续时必须再次经过原生云端发送确认；云端失败不回退本地。

合同为`contracts/agent-evals/v7-bounded-clarification.json`。前端只呈现协议选项，不提供自由文本
“澄清回答”通道。

## 结果

清晰任务仍直接进入检查/规划；信息不足时可在同一进程内继续，减少用户重复描述和再次分类。
检查点可以显示`inProcessClarification`，但不能恢复写权限。真实Qwen/Pi验收从缺目标进入澄清，
选择OpenCode后只生成OpenCode配置计划，并停在原生确认之前。

代价是协议、Rust运行时、Tauri命令和前端均需认识澄清类型；schema v2消费者必须升级到v3。应用
仍处开发初期，不引入持久会话、迁移恢复或正式升级流程。
