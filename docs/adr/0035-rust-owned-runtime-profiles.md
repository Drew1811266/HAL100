# ADR-0035：Rust拥有的个人运行方案

- 状态：已接受
- 日期：2026-08-26

## 背景

用户会反复使用经过测试的模型与推理引擎组合。只记住模型名称会丢失引擎版本、模型完整性和
设备容量策略，直接保存启动命令、路径或任意参数又会把不可验证配置和敏感本机信息变成长期
事实。Pi若依据自然语言自行拼接这些参数，也无法可靠判断组件漂移或安全恢复失败切换。

## 决策

1. `RuntimeProfileSpecV1`只描述HAL100当前拥有的本地运行身份：名称、说明、模型ID/显示名/
   SHA-256、固定`llama.cpp`版本和Rust容量档案。方案不保存模型路径、命令、环境变量、凭据、
   提示词或会话历史。
2. SQLite schema v10以`runtime_profiles`作为唯一持久化事实源。当前同一模型和引擎只允许一个
   方案；名称和说明有长度边界，方案可独立编辑或删除，删除不影响模型文件、索引或引擎。
3. 只能从正在运行且数据库已验证的本地模型保存方案。读取目录时重新比较模型可用性/哈希、
   引擎安装态/版本和容量档案，派生`Active`、`Ready`、`NeedsVerification`或`NeedsRepair`，
   不把旧验证时间当作当前可用证据。
4. 切换使用5分钟有效的一次性计划。`RuntimeProfileManager`在消费计划后再次校验方案修订和现实
   状态；目标启动失败时尽力恢复原模型，成功后更新验证快照与最近运行时间。
5. Agent RPC v13新增`activate_runtime_profile`任务与
   `hal100.plan_runtime_profile_activation`。Pi先读取脱敏运行目录并只复制精确`profileId`；
   外层计划仍须Rust原生确认，最终只接受`RuntimeProfileRecheck`现实状态。
6. 当前只覆盖HAL100托管的本地`llama.cpp`运行组合。外部后端、客户端接入和复合部署配方不伪装
   成同一种方案；若以后纳入，必须增加明确的版本化类型和独立所有权规则。

## 影响

- 用户可以保存多个经过验证的工作模式，并在组件未漂移时快速切换。
- Pi可以理解“运行代码助手方案”等任务，但不能看到路径、提交自由参数、直接启动模型或绕过确认。
- 引擎、模型哈希或容量策略变化会显式要求复验；不可用模型或缺失引擎会故障关闭。
- 方案管理增加一次SQLite迁移和一次Agent RPC版本升级，但不改变Gateway数据面或外部客户端协议。

## 非目标

本决策不实现方案云同步、导入导出、任意启动参数、自动启动、定时切换、安装包、签名、公证、
自动更新或正式升级流程。
