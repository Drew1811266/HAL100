# ADR-0032：任务级Pi上下文装配与可复核效率合同

- 状态：已接受
- 日期：2026-08-25

## 背景

内置Qwen/Pi上下文已从6144提升到16384 Token，但长窗口本身不会消除浪费。旧执行链每轮发送
覆盖全部18项工具的系统指令，并把已经消费过的早期工具结果继续带入后续模型调用；受控计划工具
成功后还会增加一个只用于复述“等待确认”的模型回合。这样既挤占长窗口，也让2B模型反复处理与
下一步无关的信息。外部Agent的HAL100受管模型配置同时仍保留4096 Token历史保守值，与当前
长任务目标不一致。

## 决策

1. 内置Pi继续使用16384 Token窗口和4096 Token安全保留区，不通过缩小容量实现效率优化。
2. Sidecar系统指令拆成固定安全基线与18项任务指令；每次运行只装配Rust已授权
   `requiredTools`对应的指令，安全、所有权、原生确认和禁止通用Shell规则始终保留。
3. Provider调用只携带原始用户目标、最新直接工具调用/结果对及最新固定纠偏提示。工具选择仍由
   完整Rust任务状态决定，不能从裁剪后的模型消息反推授权；无法证明工具调用/结果配对时保留原
   上下文并故障关闭优化。
4. 最终动作计划工具成功后立即结束Pi执行链，由固定中文说明明确“尚未执行、等待原生确认”。
   Rust计划、确认和复验不变；只读任务仍保留最后一个模型解释回合。
5. Agent RPC升级到v11。完成载荷报告上下文/输出预算、意图与执行回合、纠偏次数、Provider
   Usage、峰值输入、上下文裁剪轮次、工具结果及重复结果字节/Token估算。Rust复核全部范围和
   交叉关系后才进入公开结果与脱敏审计；不记录提示词、回答或原始工具结果。
6. 工具结果Token使用Pi相同的`ceil(可见字符数/4)`确定性估算，只用于同场景效率比较，不替代
   Gateway/Provider返回的精确计费用量。界面在“技术详情”中明确展示精确或估算口径。
7. HAL100托管用户模型和外部Agent配置统一使用版本化`managed-route-v2`：16384上下文、1024
   最大输出、parallel 1、reasoning off。Rust llama-server参数与四类适配器读取同一常量；
   Hermes的64000 Token最低要求仍故障关闭，不虚报能力。

## 结果

- v9的18条受控动作路径，旧最小回合上限55降为37，下降32.7%；计划、确认和现实复验未删除。
- 三工具旧装配对照中的重复工具结果由非零降为0，发送工具结果Token低于旧值60%，满足至少40%
  的缩减门槛。
- 真实本地Qwen模型启动计划使用16384窗口，在2个执行回合内完成，纠偏0、重复工具结果0；
  Provider精确报告总输入1375、输出391、峰值输入793 Token。
- 4096历史配置不再写入Pi Coding Agent、OpenCode或OpenClaw受管模型片段；Hermes仍要求能力
  足够的独立模型配置。

## 代价与后续

上下文裁剪依赖当前任务图为有界线性前置链。复合任务图不能简单复用“只保留最后结果”策略，
必须按节点声明直接证据依赖并在Rust中验证。Token估算不等同于账单用量；基准必须同时保留
Provider Usage可用性。后续继续完成复合任务图、证据驱动适配器扩展和长时/多设备验收。
