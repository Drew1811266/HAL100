# ADR-0012：外部 GGUF使用专用选择命令和确认索引

- 状态：已接受
- 日期：2026-08-18

## 背景

导入本地模型需要让用户选择任意位置的文件，但向 WebView开放通用文件系统能力会扩大攻击面。外部模型还必须保持用户所有权，不能因为加入 HAL100目录就被误认为可删除资产。

## 决策

1. 使用 Tauri Dialog插件的 Rust API打开原生选择器；主 WebView capability不加入`dialog:open`或文件系统权限。
2. 专用命令只接受选择器返回的单个`.gguf`路径，拒绝符号链接、目录、非UTF-8路径和重复索引。
3. 首版读取24字节固定头，验证`GGUF`标识、v2/v3版本、tensor与metadata计数安全上限；不在导入时扫描或哈希整个大文件。
4. 检查后生成最多一个5分钟、一次性的确认计划。应用前重新读取规范路径、大小、修改时间和固定头，任何变化均故障关闭。
5. 首版导入只建立`external`索引，不复制、移动、改写或删除源文件。
6. 模型、位置和不含完整路径的审计摘要在同一 SQLite事务内提交。
7. 模型页只在用户打开时检查已索引的固定文件，不递归扫描目录；大小或修改时间变化显示为`changed`，完整哈希留给用户主动验证。

## 结果

- 渲染进程不能用 Dialog插件或通用文件 API任意浏览用户目录。
- 文件选择本身不等于授权；只有可见计划确认才能产生模型记录。
- 固定头校验不能证明整个 GGUF无损或可被 llama.cpp加载，启动前仍需引擎兼容性和可选哈希验证。
- 外部文件移动后会显示缺失，HAL100不会自动搜索其他目录或删除旧源文件。
