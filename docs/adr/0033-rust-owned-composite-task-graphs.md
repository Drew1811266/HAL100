# ADR-0033：Rust拥有的复合配置任务图与非授权恢复

- 状态：已接受
- 日期：2026-08-25

## 背景

现有18类Agent任务已经具备单任务意图、工具、一次性计划、原生确认和现实状态复验，但用户要
完成“准备推理环境、启动模型并接入外部Agent”时仍需手工提交多个相互依赖的请求。直接让Pi生成
多步计划会把节点、依赖、参数和失败策略交给模型，既难以证明完整性，也可能绕过每项写操作的
原生确认。进程内单任务检查点也不能表达多个节点的依赖和补偿状态。

## 决策

1. 复合目标由Rust工厂展开为有向无环图。首批固定“安装/确认引擎→启动/确认模型→配置/确认
   外部Agent”的3节点图，以及增加HAL100私有Pi安装节点的4节点图；Pi不能提交、删除或重排
   节点和依赖。
2. 图最多8个节点，每个节点最多4个前置依赖。依赖只能引用已出现节点，构造时拒绝自环、前向
   引用、重复依赖、重复任务、混合Provider和未知补偿，因此运行期不需要信任模型做拓扑判断。
3. 节点复用现有`AgentTaskSpec`、成功谓词、证据白名单与原生动作边界。只有Rust接受的现实证据
   才能把节点标为成功并解锁后继；错误证据、模型文字或执行器摘要不能推进图。
4. 幂等已满足与实际创建HAL100所有状态分开记录。只有后者可以成为补偿候选；首批安全逆操作
   只允许引擎安装→移除、HAL100外部配置→断开、私有Pi安装→私有移除。
5. 补偿不会自动执行。图失败或取消后，调用方必须按逆序显式发起，每个补偿仍需新的一次性计划、
   原生确认和现实复验；每个节点最多尝试一次，补偿失败故障关闭。
6. 图检查点schema v1只保存节点序号、依赖序号、任务/目标类别、成功谓词、枚举状态、枚举证据、
   是否改变HAL100所有状态和计数。不保存提示词、回答、具体资源、计划/run ID、参数、路径、凭据
   或原始结果。
7. 检查点不是授权。重启恢复必须由调用方重新提供精确目标定义；Rust只用检查点验证图形状，随后
   将所有节点重置为依赖派生的`ready/blocked`状态。旧成功、运行、确认和补偿状态都必须重新读取
   现实并为写操作重新规划、确认。

## 结果

- Core已经实现图构造、依赖解锁、证据拒绝、失败传播、取消、失权、逆序单次补偿、脱敏检查点
  和重启重验证；代表性3/4节点Rust工厂已固定。
- `contracts/agent-evals/v10-composite-task-graphs.json`记录12类语义和零自动补偿、零恢复授权门槛。
- 协议与桌面状态模型可以携带可选的脱敏图检查点；桌面已接入逐节点Sidecar、一次性计划、原生
  确认、动作复验和Agent页面控制，但仍不开放自动批量执行。
- 执行前Rust现实状态预检会以`AlreadySatisfied`完成幂等节点；真实Pi首段图验收由此把模型回合
  从9降至3，并在模型计划生成后停于确认，没有执行写操作。
- 桌面只在同一成功谓词由执行前`Unsatisfied`变为执行后`Satisfied`时记录
  `ChangedOwnedState`；未知前态、幂等满足和执行器摘要均无补偿资格。失败或取消后，用户可显式
  发起Rust固定逆序补偿，每项仍需新Sidecar计划、原生确认和现实复验。
- 隔离OpenCode纵向已完成配置→下游失败→显式断开补偿；两次写入使用不同一次性计划和确认，
  图最终由断开复验证据进入`compensated`，全程没有自动补偿。
- v11恢复合同把非终态图保存为不超过16KiB的0600原子JSON；未知字段或错误形状拒绝。重启只
  暴露语义形状，用户重新选择精确目标后Core清空全部旧证据、变更与授权并从现实重验证；成功或
  已补偿终态清理恢复文件。
- 最终真实Pi隔离纵向以0回合幂等完成引擎/模型节点，以2个真实模型回合生成OpenCode计划；伪造
  计划拒绝，精确计划经确认路径执行并由`IntegrationRecheck`完成，整图`succeeded`且无用户配置
  写入。

## 代价与后续

重启后重新复验会增加少量确定性读取，但避免把脱敏、缺少资源身份的历史摘要当作授权证据。
本决策的完成条件已满足。后续新增图工厂仍必须复用本文的单节点授权、真实变更归属、显式补偿和
非授权恢复边界；持久化继续只能保存脱敏形状，精确目标必须由安全的用户选择重新绑定。
