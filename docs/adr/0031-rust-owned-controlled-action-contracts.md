# ADR-0031：Rust拥有的受控动作契约与组合式纵向证据

- 状态：已接受
- 日期：2026-08-25

## 背景

HAL100已有18类任务、一次性计划、原生确认、确定性执行器和动作专属复验，但“任务允许哪种
原生动作”仍分散在完成校验、计划构建器和执行分支中。外部Agent配置/断开还需要分别证明四个
适配器，诊断修复则有界复用引擎安装、外部Agent配置和失效模型索引移除三个执行器。只按任务
数量列清单会漏掉实际执行变体，也无法自动发现公开计划与私有执行器的错误配对。

## 决策

1. `AgentTaskKind`由Rust Core返回允许的`AgentActionKind`集合：10类受控任务覆盖9种原生动作；
   只读任务集合为空，诊断修复只允许现有3类确定性修复执行器。
2. 结构化任务完成校验使用当前`AgentTaskSpec`核对动作类型；旧零工具兼容路径仍使用原有能力
   校验，不借机扩大权限。
3. 一次性计划注册前必须证明公开动作类型、公开目标、原生确认要求与私有Rust执行器一致；错误
   配对不能进入原生确认界面。
4. `v9-controlled-action-verticals.json`以18条路径展开任务和适配器变体，固定自然语言入口、精确
   工具集合、允许动作、下层隔离执行验收及复验证据来源。
5. 纵向验收采用组合式证据图：v9合同测试验证所有引用存在且属于默认门禁；同一次`pnpm check`
   实际运行被引用的隔离执行、回滚、状态机和复验测试。测试只能使用临时HOME、临时数据目录、
   回环服务或合成文件，不读取和修改用户真实配置。

## 结果

- 10/10受控任务、9/9原生动作、四适配器配置4/4与断开4/4、诊断修复3/3均有绑定证据。
- 幂等、取消、过期、目标变化、执行失败、复验不满足、证据不可用和回滚恢复8类失败均进入默认
  门禁。
- Pi仍不能提交工具、执行器、证据或权限；签名、公证、安装包、自动更新和正式升级流程不在
  本决策范围。

## 代价与后续

组合式证据图不是为每条路径复制一个昂贵的单体测试函数；它依赖版本化合同把路由、计划、执行
和复验的默认测试连接起来。新增任务、动作、适配器或执行器时，必须同步更新Core允许关系、v9
路径和文档一致性门禁。下一阶段继续量化模型回合和重复工具结果Token，不以减少验证换取效率。
