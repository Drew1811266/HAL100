# ADR-0011：按需硬件画像与统一模型目录

- 状态：已接受
- 日期：2026-08-18

## 背景

模型搜索、下载和启动需要知道统一内存、磁盘余量及模型所有权，但 HAL100又必须长期低成本驻留。Hugging Face和ModelScope还需要共用同一模型记录和下载状态机，不能形成两套不可迁移的数据结构。

## 决策

1. 硬件画像只在模型页首次打开、用户刷新或 Agent明确调用只读工具时执行，不加入后台轮询。
2. macOS实现使用绝对路径的系统程序和固定字段；WebView不提供命令、字段或探测路径。
3. 推荐范围由 Rust确定性规则生成，并作为保守提示，不让 Agent模型猜测硬件或承诺性能。
4. 默认下载源是可空用户设置；未选择时不隐式偏向任一服务。
5. 两个远端来源共用`models`、`model_locations`和`downloads`，模型记录始终保存实际来源。
6. `managed`与`external`所有权在首次入库时确定，后续删除规则以此为授权依据。
7. 安装、下载、托管复制和删除使用后续独立的确认计划；硬件只读和默认源设置不伪装成这些高风险接口。

## 结果

- 后台隐藏状态不会因为硬件画像产生新增唤醒或常驻进程。
- 模型管理可以在未来 Windows实现同一协议和数据库结构，只替换平台探测器。
- 模型推荐不会实时反映其他应用突然占用的内存；下载和启动前仍需进行即时资源检查。
- 当前 macOS开发版启动两个短生命周期系统进程完成一次探测，后续若采样频率提高必须改为原生 API。
