# ADR-0018：部署就绪检查与有界短时观测

日期：2026-08-21

## 状态

已接受。

## 背景

HAL100已经能够诊断环境、读取脱敏运维历史，并通过原生确认执行确定性的引擎、模型和外部Agent配置事务。下一步需要帮助用户判断部署是否具备前置条件，以及区分稳定配置问题和瞬时运行问题。

直接向Pi Agent Core开放Shell、包管理器、原始日志或长期后台监测，会把模型推理、供应链执行和系统权限混成同一信任边界。外部Agent安装命令及下载源也会随版本和平台变化，不能在缺少签名配方、来源固定和回滚模型时仓促固化。

## 决策

- Agent RPC升级到v7，新增只读能力`hal100.observe_operational_health`。
- 参数必须精确等于`{"target":"deployment","sampleCount":3}`；额外字段、扩大样本数或请求原始日志全部拒绝。
- Rust先执行一次既有全面诊断，再在约200毫秒固定窗口内采集3次Gateway路由、后端熔断和引擎运行状态；每个等待点都响应任务取消。
- 返回值只包含安装/就绪计数、固定故障码和聚合采样，不包含后端ID、目标ID、路径、配置、凭据、提示词、回答或原始日志。
- 观测任务随当前Agent任务结束，不注册计时器、不创建后台守护任务，也不声称替代长期监控系统。
- 可安全修复的问题继续使用既有诊断修复或专用配置计划；观测结果本身不是授权令牌，也不新增写权限。

## 结果

HAL100可以回答部署前检查和短时运行稳定性问题，并把证据交给本地或用户明确授权的云端模型解释，同时保持Rust Broker为唯一系统观察与执行权威。

后续外部软件安装能力必须先建立版本化受管配方：固定软件身份、可信来源、完整性校验、用户级目标、命令与参数白名单、预览、原生确认、超时、取消、写后验证和可恢复策略。在此之前不开放通用包管理器或任意命令执行。
