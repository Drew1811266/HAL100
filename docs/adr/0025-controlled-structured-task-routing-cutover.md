# ADR-0025：结构化任务路由受控接管

- 状态：已接受
- 日期：2026-08-25
- 关联：ADR-0021、ADR-0022、ADR-0023、ADR-0024

## 背景

迭代34已经证明内置Qwen能在固定长尾合同中稳定提出有界任务，但裁决结果仍是影子数据。
`agent.run.start.requiredTools`继续由Desktop旧关键词函数计算，因此Pi即使把长尾配置请求正确识别
为“配置外部Agent”，旧路由也可能只下发检查工具。任务理解与实际能力选择之间仍存在断点。

直接让Pi输出工具会绕过Rust工作流；无条件回退旧关键词又会重新引入已知误判。需要让结构化
任务成为能力选择依据，同时为守卫、未解析、兼容解释和开发期回滚分别定义明确行为。

## 决策

1. 每个`AgentTaskKind`在Rust Core中映射一个叶能力。能力注册表从叶能力递归闭合前置能力并
   产生规范顺序；Pi提案仍不得包含工具名、参数、Provider、确认或授权。
2. `Agreement`、`DeterministicOnly`和`ProposalCandidate`选出的`AgentTaskSpec`在默认
   `controlled`模式下接管`requiredTools`。外部Agent目标从已验证任务目标解析并绑定Tool
   Broker，不能继续使用提示词猜测出的不同目标。
3. 确定性`Clarify`或`Reject`由Rust返回固定中文回答，不启动Agent Model Runtime或Kernel，
   不创建临时Gateway凭据，不进入`agent.run`，不调用工具。
4. Pi提出的澄清或拒绝在意图回合后同样由Rust固定收口。裁决没有可信任务时：
   - 旧能力集合非空则故障关闭，不调用工具；
   - 旧能力集合为空时才允许零工具解释兼容路径继续运行。
5. 开发期允许在启动环境设置`HAL100_AGENT_TASK_ROUTING_MODE=safe-legacy`进行立即回退。该模式
   只允许确定性已经识别的任务使用旧能力集合；确定性`Unresolved`而仅由Pi识别的任务仍故障
   关闭。未知环境值回到默认`controlled`并只记录固定错误码。
6. `AgentStatus`公开当前路由模式和进程内`AgentTaskRoutingMetrics`。指标只聚合六类路由决策
   计数与更新时间，不保存提示词、回答、任务类型、目标、run ID、路径或凭据，重启后清空。
7. 所有变更能力仍只生成Rust一次性计划。接管不改变Tool Broker复验、单计划预算、原生确认、
   现实状态复验和确定性Executor。

## 结果

- 结构化任务和实际工具集合不再漂移；长尾Pi任务能获得工作流所需的精确前置能力和计划能力。
- 安全拒绝比以前更高效：确定性守卫不再为了生成拒绝回答而加载1.28 GB模型。
- 未解析、模型失败和安全回退不会把有工具请求交回已知不准确的关键词路径。
- 无工具的HAL100解释类能力保持兼容，不强迫18类任务合同承载通用说明问题。
- 开发者可以观察接管、兼容和故障关闭比例，但不能从指标重建用户请求。

## 未选择方案

- 让Pi直接返回`requiredTools`：跨越Rust工作流和能力注册表边界。
- 把结构化任务与旧关键词工具集合取并集：会扩大数据范围，并可能形成多个写计划。
- 所有未解析请求都回退旧路由：重新引入长尾外部Agent误判和越权风险。
- 所有未解析请求都报错：会破坏当前合法的零工具产品说明能力。
- 通过持久化提示词或任务目标观测接管：违反默认不保存用户内容的边界。
- 本轮直接执行写操作：当前Agent工具只生成计划，用户原生确认与确定性执行必须保持独立。

## 范围说明

本决策只涉及开发期Agent任务路由、能力派生和进程内观测，不涉及签名、公证、安装包、自动
更新、正式升级或正式发布流程。
