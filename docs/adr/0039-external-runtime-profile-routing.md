# ADR-0039：外部运行方案完整路由与实时证据闭环

- 状态：已接受
- 日期：2026-08-27

## 背景

ADR-0038只建立了外部Ollama的只读候选。直接把候选保存并复用现有“活动后端”切换会产生两个
结构性错误：Gateway收到保留模型名`hal100-active`时仍会把它原样发给Ollama，而不是方案中
经过验证的真实模型；托管llama.cpp临时接管后也只恢复旧后端，无法恢复外部模型选择。

外部服务和模型还可能在候选展示、保存、用户确认和实际切换之间变化。界面快照、Pi输出、
Gateway路由匹配或执行器返回值都不能单独证明“原来验证过的组合当前仍然成立”。同时，Ollama
属于用户，HAL100不能因为保存了方案就取得安装、进程或模型生命周期权限。

## 决策

1. Gateway以`ActiveGatewayRoute { backend, resolved_model }`作为唯一运行时活动对象。
   `hal100-active`在存在解析模型时改写为真实模型；普通别名语义保持不变。SQLite schema v12在
   一个事务中持久化完整活动路由和旧兼容后端字段。
2. 托管引擎会话启动前保存完整活动路由。正常停止、强制停止和崩溃恢复均还原后端与解析模型，
   不能只恢复后端。
3. 运行方案升级为spec v2/schema v12并显式区分`managed`与`external`。托管身份要求本地
   SHA-256和容量合同；外部身份要求后端ID、规范API根、引擎版本、模型名和Ollama digest，容量
   保持为空并表达为“由引擎决定”。两类身份使用独立唯一索引。
4. 本地发现与运行方案管理器共享`ExternalInferenceEngineRegistry`。注册表只接受外部、非托管、
   引擎类型唯一的适配器。Ollama适配器继续只有固定回环只读检查能力。
5. 保存外部方案时，Rust不信任WebView候选：重新读取已保存且启用的后端、API根、实时版本、
   完整模型目录和精确digest。并发保存与激活通过异步互斥串行化，数据库唯一约束作为第二道门禁。
6. 预检只为与保存版本和digest完全一致的外部身份签发短期一次性计划。执行前再次检查，切换后
   再次检查外部服务和完整活动路由；任何漂移、后端变化、模型缺失、路由不匹配或数据库提交失败
   都拒绝成功，并恢复先前持久化路由及必要的托管运行状态。
7. `catalog_verified`按引擎批量复用一次实时探测，为桌面和Pi目录更新不可用、身份变化、版本变化、
   模型缺失与digest变化。仅路由匹配不能保持“正在运行”状态。外部身份漂移只能由桌面在Rust
   原生确认后显式重验；重验只更新验证锚点，不启动、安装、拉取或切换模型。
8. Pi目录只增加方案所有权、保存的非秘密后端ID和可选容量，不包含API根、digest或内部计划ID。
   Pi可以用精确`profileId`请求Rust实时预检并生成外层一次性计划；Rust继续独占重验、原生确认、
   活动路由写入、执行和最终现实证据。外部方案的最终`RuntimeProfileRecheck`必须再次访问引擎。

## 安全与恢复不变量

- 候选、界面状态、Pi文字、工具返回成功和路由匹配都不是执行授权或最终完成证据。
- 计划绑定方案更新时间、所有权、后端、模型、实时版本和digest，只保留最新且只能消费一次。
- 外部切换失败后，数据库与Gateway内存路由必须回到同一个旧值；先前托管模型若被停止则尝试
  恢复。恢复结果进入类型化错误，不以成功文案掩盖。
- Agent不会获得外部快照重验、Ollama安装、模型pull/delete、进程启停、任意URL、Shell或文件
  操作能力。
- 所有探测按需发生；不新增常驻轮询、后台监控或Gateway请求热路径HTTP检查。

## 影响

- 外部Ollama现在可以成为多个可复用的个人运行方案，同时保持用户所有的生命周期边界。
- 完整活动路由解决了`hal100-active`转发错误，并允许托管与外部方案安全往返。
- 桌面与Pi看到同一套实时漂移结论；同一外部引擎的多个方案不会重复发起目录请求。
- 协议和数据库处于开发期内部演进；v11方案迁移为托管所有权，不形成正式升级承诺。

## 非目标

本决策不安装、卸载、启动、停止或升级Ollama，不拉取、创建或删除Ollama模型，不实现Windows或
Linux桌面应用，也不引入签名、公证、安装包、自动更新、正式升级或发布流程。
