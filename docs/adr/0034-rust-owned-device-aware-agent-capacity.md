# ADR-0034：Rust拥有的设备感知 Agent 容量档案

- 状态：已接受
- 日期：2026-08-26

## 背景

ADR-0028把内置Qwen/Pi从6K提高到16K，解决了首批工具工作流的明显容量不足，但运行时、
Sidecar和外部Agent模型描述仍分别持有固定常量。随着任务级上下文和复合配置图接入，16K仍可能
过早压缩有效目标与工具观察。直接统一提高到模型原生上限，或让模型/用户选择容量，又会把最低
设备的内存、延迟和稳定性风险变成未经验证的运行时行为。

## 决策

1. 容量选择权只属于Rust。桌面启动时读取一次统一内存，不启动硬件轮询，也不保存硬件标识。
2. `agent-runtime-v2`当前只定义两个经过合同约束的档位：低于16 GiB使用`baseline16k`；16 GiB
   及以上使用`standard32k`。更大内存当前仍选32K，不能从设备容量自动外推未验收64K。
3. Pi保留区固定4096 Token，两档可用输入分别为12288和28672 Token；最大输出仍为768，
   `parallel 1`、`reasoning off`和温度0保持不变。
4. 同一不可变档案驱动内置Agent llama.cpp、HAL100托管用户模型和受管外部Agent模型描述。
   `managed-route-v3`只改变上下文来源，不扩大工具、文件或执行权限。
5. Agent RPC升级到v12。Rust在意图与执行请求中显式发送`contextWindowTokens`和
   `maxOutputTokens`；Sidecar只接受本地16K/32K或固定云端128K/2048，合同外数值故障关闭。
6. 状态接口与Agent技术详情显示当前档位和上下文；模型输出、提示词、远端响应及用户文本均不能
   提高档位。

## 证据

- Apple M1/16 GiB、Qwen3.5-2B Q4_K_M、llama.cpp b10218在32K下完成27,725 Token真实输入，
  无截断并准确返回预期计数；总耗时73.12秒，提示吞吐380.09 Token/s。
- 推理期间`vmmap`物理占用峰值566.3 MiB；探针停止后进程和监听端口均回收。
- 隔离真实Agent冷启动取消为0毫秒，活跃推理取消为75毫秒，最终内置运行时和Sidecar均停止。
- 隔离真实复合图在RPC v12/32K下保持0/0/2模型回合、重复工具结果0，确认写入后仍只由
  `IntegrationRecheck`完成。
- 版本化设备选择边界矩阵达到7/7，覆盖未知内存、8 GiB、16 GiB阈值前后、24 GiB及64/128 GiB
  仍封顶32K；这些是策略边界测试，不冒充对应硬件性能实测。
- 同一隔离32K运行时连续20轮真实Pi只读配置任务达到20/20，最大2执行回合、重复工具结果0；
  213.655秒后显式停机，活动任务和Kernel/模型子运行时均为0。

## 代价与后续

16 GiB阈值是当前最低标准档的实测边界，不是模型能力推断。8/12 GiB设备继续使用16K，32 GiB
以上设备暂不获得更高窗口。开放24K中间档、64K或基于运行压力的动态档，都必须新建最低设备
实测、取消/回收、重复任务稳定性和版本化合同；运行中的档位不热切换。

本决策不增加任意Shell、文件系统、桌面自动化、root、云端回退或历史提示持久化，也不涉及签名、
公证、安装包、自动更新或正式升级流程。
