# ADR-0009：主 WebView 隐藏复用

- 状态：已接受
- 日期：2026-08-17
- 替代：ADR-0003 和 ADR-0007 中“关闭主窗口即销毁 WebView”的部分

## 决策

HAL100 仍由单个 Tauri/Rust 主进程长期驻留，不引入独立系统守护进程。登录启动且用户尚未打开界面时可以不创建 WebView；主 WebView 一旦创建，用户关闭主窗口时阻止销毁、改为隐藏，并在托盘或单实例唤起时复用。只有明确退出 HAL100 才随进程释放主 WebView。

隐藏状态下前端必须暂停轮询、动画、图表刷新和其他周期任务。React 状态仍不是持久化事实源，Rust Core 和 SQLite 仍是权威状态。诊断窗口等临时窗口不适用该复用规则。

仅 `benchmark-hooks` feature 保留强制 `destroy` 压力模式，用于观察 Tauri/WebKit 的回收行为；产品路径不调用该模式。

## 原因

迭代1的真实回归发现，macOS WebKit 在同一进程中高频销毁和重建主 WebView时会保留逐步增长的进程内资源：50轮压力测试中物理占用从约43.2 MiB升至约70.9 MiB，100轮测试仍呈增长趋势。虽然进程退出后资源能完全回收，但这不适合长期驻留软件。

改为生产路径隐藏/显示同一个 WebView后，100轮回归的物理占用从约42.3 MiB降至约39.4 MiB，峰值约42.5 MiB，没有随轮次增长。关闭后空闲 CPU的6次采样为0.0%、0.3%、0.1%、0.2%、0.1%、0.0%，满足不高于0.3%的预算。

## 后果

- 主窗口关闭后的基线物理占用约41 MiB，仍低于80 MiB后台预算。
- 关闭和重新打开不再承担 WebView冷启动，也不会积累反复销毁造成的资源增长。
- 前端新增任何计时器、订阅或动画时，都必须同时实现隐藏态暂停和恢复验证。
- 后续 Tauri/WebKit升级仍运行 `destroy`诊断回归；只有实测证明回收稳定且改变策略有明确收益时，才通过新 ADR调整本决策。
