# ADR-0026：进程内脱敏 Agent 任务检查点

- 状态：已接受
- 日期：2026-08-25
- 关联：ADR-0021、ADR-0023、ADR-0025

## 背景

迭代31已在Core定义`AgentTaskState`，但迭代35完成结构化路由接管后，真实运行、一次性计划、
原生确认和执行器仍各自维护生命周期。界面只能看到运行ID和计划，无法区分任务正在检查、等待
确认、执行、复验还是已经终止；计划过期也只有再次访问时才显现。

直接保存提示词、回答、工具结果或完整任务目标可以重建更多上下文，却会扩大隐私面。把待确认
计划持久化又会使应用重启看起来能够恢复旧授权，与一次性原生确认的安全语义冲突。

## 决策

1. Desktop Rust新增单任务`AgentTaskRuntime`，内部持有Core的`AgentTaskSpec`和`AgentTaskState`。
   只有经过双路裁决并被受控路由接受的任务才进入该运行态；Rust仍是唯一状态转换权威。
2. 只读任务沿`Inspecting → Verifying → Completed`结束。受控变更任务沿
   `Inspecting → Planning → AwaitingConfirmation`暂停，并且只把同一个一次性外层计划ID保留在
   私有内存关联中。
3. 原生确认只能用精确、未过期、未消费且与当前检查点关联的计划进入`Executing`。执行器成功后
   必须经过`Verifying`再完成；确定性管理器返回的写后验证结果是主要证据，环境诊断复查作为
   有界补充结果返回。执行或复验失败进入`Failed`。
4. 用户取消确认、任务取消、新任务替换或计划过期都会同时撤销外层和底层计划，并把非终态任务
   置为`Cancelled`。伪造ID不得消费计划或推进检查点。读取Agent状态时会按固定截止时间回收
   过期计划，不增加后台轮询。
5. `AgentStatus`增加schema v1的`AgentTaskCheckpoint`。它只包含任务类型、目标类别、期望状态、
   Provider类别、数据范围、阶段、序列、待确认布尔值、复验状态、恢复范围和更新时间；不得包含
   提示词、回答、资源ID、计划ID、run ID、路径、凭据、工具参数或原始工具结果。
6. 检查点和计划都不写SQLite。唯一允许的恢复范围是同一HAL100进程内继续当前原生确认；应用
   重启后检查点与计划同时消失，不自动重放模型、工具或系统操作，也不把旧确认恢复为权限。
7. 本轮不升级Agent RPC v10、不增加Pi工具、不改变Gateway数据面或SQLite schema v9。检查点是
   Desktop状态DTO，不发送给Pi，也不作为Tool Broker授权输入。

## 结果

- 用户和测试可以看到任务从理解到复验的真实阶段，而不是把“模型回答完成”误认为“配置完成”。
- 等待确认成为唯一可在进程内继续的阶段；取消、过期、伪造和重启均不能恢复执行权限。
- 检查点足以支持界面状态和确定性评测，但不能重建用户内容、具体资源或工具输出。
- 状态更新只发生在已有任务、确认、执行和显式状态读取路径，不引入常驻计时器或数据库迁移。

## 未选择方案

- 持久化完整任务上下文：违反默认不保存用户内容和本地目标的边界。
- 重启后恢复待确认计划：会把旧进程的临时授权错误延长到新进程。
- 让Sidecar或模型提交阶段：模型输出不能成为任务状态事实源。
- 只在前端推断阶段：WebView状态不是长期事实源，也无法覆盖执行器错误和计划过期。
- 把宽泛环境诊断作为所有动作的唯一成功谓词：动作适配器拥有更精确的写后验证语义。

## 范围说明

本决策只完善开发期Agent任务生命周期和脱敏状态，不涉及签名、公证、安装包、自动更新、正式
升级或正式发布流程。
