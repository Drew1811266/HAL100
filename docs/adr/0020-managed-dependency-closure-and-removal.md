# ADR-0020：受管依赖闭包与可恢复卸载生命周期

- 状态：已接受
- 日期：2026-08-21
- 决策范围：Pi私有部署供应链、受管所有权、卸载、用户安装共存
- 延续并关闭：[ADR-0019](0019-versioned-managed-agent-deployment.md)中的传递依赖残余风险

## 背景

ADR-0019固定了Pi Coding Agent顶层npm包、版本、Registry和SRI，但npm仍会按上游依赖范围解析传递依赖。即使顶层归档不变，Registry中新发布的兼容版本也可能改变实际执行代码。与此同时，只有安装没有受管卸载会形成不完整生命周期；若把“卸载Pi”直接映射为文件删除，又可能误伤用户自行安装的官方Pi、`~/.pi`配置或会话。

## 决策

### 固定完整npm闭包

- Pi配方继续固定`@earendil-works/pi-coding-agent@0.84.2`和顶层SHA-512 SRI。
- npm只在HAL100 owner-only UUID暂存目录中运行；当前工作目录固定为该目录，环境清空，PATH只增加已复验npm同目录的Node与固定系统目录。
- HAL100写入最小私有`package.json`，从已验证的本地tgz安装，禁用所有生命周期脚本，并要求生成lockfile v3。
- Rust拒绝绝对路径、父目录、非官方Registry来源、缺失版本/来源/SRI或异常link条目。
- 对全部136项非根包投影版本、来源、SRI、依赖、可选依赖、Peer依赖/元数据、引擎、OS、CPU、bin和安装语义标记；递归排序JSON后计算SHA-256。
- 闭包指纹固定为`4898c398887684b0fd367f15e75d01b98305a97db2fc805e9ebb0560d2520c37`。任何上游解析漂移都要求显式更新配方和重新验收，不允许“兼容范围内自动接受”。
- 顶层归档和闭包都通过后，才允许执行私有`pi --version`；随后原子启用`runtime`。失败只清理本次暂存目录。

### 区分三种生命周期

1. “断开Pi接入”只移除HAL100受管配置片段和专属凭据，不卸载任何CLI。
2. “卸载HAL100私有Pi”只移动应用数据目录中的固定`runtime`。
3. 用户自行安装、升级或卸载官方Pi不属于HAL100执行范围。

RPC v9的检测结果增加`managedInstallation`。私有卸载工具要求同一任务先检测同一`integrationId`，用户提示还必须明确包含HAL100私有/受管语义；含糊的“卸载官方Pi”只允许返回边界说明，不能生成文件计划。

### 可恢复卸载

- 预览时验证托管根和runtime不是符号链接，规范路径精确位于固定集成根下，并验证包版本、入口和闭包指纹。
- 计划只在Rust内存保存规范路径和闭包快照，五分钟有效且单次消费。
- 原生确认后再次执行相同验证；缺失、变化或所有权异常均拒绝。
- runtime先在同一父目录原子改名为随机隔离目录，再调用系统废纸篓。
- 废纸篓失败且隔离目录仍存在时立即改名恢复；无法恢复使用独立固定错误码，避免把“卸载失败”误报成原目录仍完好。
- 用户Pi候选、`~/.pi`配置、凭据和会话不参与枚举、快照或文件操作。

## 模块边界

- `ManagedExternalAgentDeploymentManager`：配方、归档/闭包校验、私有runtime安装和卸载。
- `PiCodingAgentIntegrationAdapter`：用户优先的CLI检测和Gateway配置事务；不拥有私有runtime文件操作。
- `agent_coordinator`：区分安装、私有卸载、断开配置和含糊用户卸载意图。
- `agent_tools`：要求同目标状态前置，只向模型暴露布尔所有权和脱敏计划。
- `AgentService`与Tauri命令：计划废弃、原生确认和确定性执行。
- Sidecar：RPC/TypeBox编排；不获得npm、路径、废纸篓或文件系统能力。

## 被拒绝的方案

### 只锁顶层包

不能约束传递依赖范围解析，拒绝。

### 接受任意新解析闭包

会把Registry时间变化变成未评审代码升级，拒绝；配方更新必须显式发生。

### 删除runtime而不进废纸篓

降低误操作可恢复性，拒绝。

### 通用“卸载外部Agent”工具

不同软件的安装位置、包管理器、配置和所有权语义不同，无法由一个开放参数工具安全推断，拒绝。后续Agent必须各自提供经过验收的版本化配方。

## 后果

Registry合法发布新传递版本后，旧Pi配方可能故障关闭，开发者需要解析、审查和更新闭包指纹。这是有意的供应链升级门槛，不是可用性缺陷。lockfile验证约束解析结果，但HAL100仍依赖用户已有的受支持Node/npm和在线Registry；离线运行时供应不在本迭代范围。

本决策不增加通用Shell、全局包管理、任意文件读写、Accessibility、Screen Recording、Apple Events、root Helper或桌面自动化权限。
