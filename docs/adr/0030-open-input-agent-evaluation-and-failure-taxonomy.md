# ADR-0030：开放输入 Agent 评测与失败分类

- 状态：已采纳
- 日期：2026-08-25

## 背景

早期配置合同和真实Pi合同规模小，且措辞逐渐被确定性路由、提示示例和UI模板覆盖。固定集全绿
不能回答口语、省略、混合语言、冲突动作和新对抗表达是否仍能被正确理解，也容易诱导开发者为
单个失败堆叠关键词。

## 决策

HAL100新增独立v8开放中文合同，并采用两层评测：

- 41个主场景与UI模板、v1和v3原句隔离，覆盖18类任务、三类澄清、零工具解释、冲突和对抗；
- 确定性层记录精确率、主动交给Pi的数量、越权任务数和失败类别，但不要求把所有自然语言固化为
  关键词；
- 12个确定性未解析的独立Pi场景每项重复2轮，只运行意图分类，不注册工具；
- 失败固定分为错误处置、错误任务、错误目标、不必要澄清、过度拒绝、拒绝不足、安全任务未解析
  和无效提案；
- 只有稳定复现且能保持边界的修复才能进入路由或提示。不得为提高得分扩大工具、文件、Shell、
  桌面自动化、root或云端回退权限。

当前真实Pi门槛为结构化≥95%、语义≥85%、安全=100%；确定性层硬门槛是越权任务数为0。开放
合同不替代全部动作的现实状态纵向验收。

## 结果

评测区分了“合理交给Pi”与“确定性错误授权”，避免用确定性词表覆盖所有语言。首次基线直接
发现root/桌面自动化未被确定性拒绝，以及非外部任务输出容易携带非法targetId；前者补为Rust
守卫，后者通过目标字段规则与六类非外部示例修复。诊断/修复的稳定混淆再以互斥语义修复。

仍有一个单目标相互矛盾动作缺少专属澄清槽位；在该语义被设计前不得伪装成现有“选择唯一目标”
澄清。应用继续不保存开放提示或模型回答，测试输出只保留场景ID和聚合指标。
