# 迭代11：环境诊断与受控修复验收

日期：2026-08-19
平台：Apple M1、16 GiB统一内存、macOS Apple Silicon开发机
软件：HAL100 `0.0.1-dev.0`、Pi Agent Core `0.84.2`、Qwen3.5-2B Q4_K_M、Agent RPC v3

## 验收目标

- 证明直接环境诊断是用户触发、低开销、无Qwen启动和无后台轮询的路径。
- 证明Pi只能依据Rust诊断报告生成一个非执行计划。
- 证明没有安全可修复项时可以正常结束，不伪造计划。
- 证明修复计划前重新验证状态，执行仍由原生确认独占。

## 结果

| 项目 | 结果 |
| --- | --- |
| 真实开发数据直接诊断50次 | 6 ms总墙钟；每份报告不超过64项 |
| 真实Qwen只读诊断 | 通过；17.01 s；1个诊断工具事件；0个计划 |
| 真实Qwen诊断修复意图 | 通过；24.64 s；0或1个计划；未执行 |
| Sidecar源码测试 | 22/22通过 |
| React桌面测试 | 15/15通过 |
| Rust全Workspace非忽略测试 | 通过 |
| 全量质量命令 | `pnpm check`通过 |

直接诊断墙钟数据来自忽略式真机探针`real_environment_diagnostic_snapshots_stay_bounded`。该路径只刷新廉价文件状态和SQLite快照，并读取引擎、Gateway和OpenCode检测状态；它不加载1.28 GB Agent模型。两个真实Qwen任务的时间包含模型校验、冷启动、Pi推理、工具往返和回收，因此不代表直接诊断按钮的延迟。

## 安全与状态验证

- 诊断DTO没有模型路径、OpenCode配置路径、API Key或原始日志。
- `reportId`只关联当前Agent任务；Rust从内存中的实际报告查找`findingId`。
- 缺失模型索引计划会先刷新状态并要求仍为`Missing`，避免文件恢复后误走删除流程。
- OpenCode配置计划要求仍为“已安装且未配置”；冲突或外部修改拒绝。
- llama.cpp安装计划要求仍未安装；校验失败不会被覆盖式自动修复。
- 计划生成不执行；真机验收结束时主动废弃任何测试计划并停止Agent运行时。

## 性能结论

新增能力不会改变HAL100的闲置后台成本，因为没有新增循环、轮询或常驻Sidecar。直接诊断只在按钮或Agent工具调用时同步执行；Agent模型仍在任务结束后进入既有2分钟空闲退出策略，测试显式停止运行时。
