# 迭代5故障策略与本机发现审查记录

- 日期：2026-08-18
- 环境：Apple M1、16 GiB、macOS、Rust 1.97.1、Node.js 24.18.0
- 范围：后端错误分类、有限重试、熔断、连接诊断、本机后端按需发现和中文状态
- 结论：故障策略与本机发现子阶段通过；强制切换随后已完成并单独验收

## 故障策略

- 连接失败、响应流异常和后端5xx计入各后端独立的连续基础设施失败。
- 连续3次失败后熔断15秒，新请求获得`backend_circuit_open`；成功响应会清零失败状态。
- 熔断使用Gateway启动后的单调相对时刻和原子字段。冷却到期由下一次请求或状态读取惰性处理，没有后台线程、轮询或定时任务。
- `route_draining`、`backend_circuit_open`、传输、流、响应过大和认证错误继续按OpenAI或Anthropic错误外壳返回。
- 只有幂等的`/v1/models`与显式连接诊断在传输错误或502/503/504时最多重试1次，间隔25毫秒。
- Chat Completions、Responses和Messages POST从不自动重试，避免重复生成、重复工具执行和潜在云端重复计费。

## 发现与诊断

- 中文后端页可按需诊断已加载后端，展示连接结论、HTTP状态、总延迟和Models数量；成功诊断可关闭既有熔断。
- “发现本机服务”只检查3个代码固定的IPv4回环候选：Ollama `11434`、vLLM常用`8000`和llama.cpp Server常用`8080`。
- 单目标连接超时350毫秒、总超时1秒、最多重试1次；响应以流式上限1 MiB读取。
- 探测不读取进程列表，不扫描端口范围，不访问局域网，不接受前端提供的目标URL。
- 发现项明确显示为候选，用户进入标准后端编辑器检查后才会保存；不会自动取得外部进程管理权。

## 性能复测

加入每请求一次熔断原子读取后，预热并各采样200次：

| 路径 | p95 |
| --- | ---: |
| 直接模拟后端 | 236 μs |
| 经HAL100 Gateway | 513 μs |
| 附加延迟 | 277 μs |

附加p95继续低于5 ms预算。发现、诊断与重试都只存在于用户请求作用域，隐藏界面或空闲后台时不会产生额外活动。

## 自动化证据

- Gateway单元测试覆盖连续失败打开熔断、无定时器冷却和成功恢复。
- 真实HTTP测试证明Models在首次503后只重试1次，同一后端的推理POST遇到503只发送1次。
- 连接诊断通过真实Models响应返回健康状态和模型数。
- 发现测试覆盖首次失败后的单次重试、Ollama版本解析、固定回环限制和嵌入凭据URL拒绝。
