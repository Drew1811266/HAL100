# 迭代29：用量可视化职责分离

- 日期：2026-08-24
- 版本：1.0.2 后续开发线
- 结论：通过

## 信息职责

- Token趋势：支持年、月、周、天四档，分别按月、日、日和小时聚合；三条折线比较缓存命中输入、缓存未命中输入和输出Token，图例显示所选范围内各项合计。
- 请求活跃热力图：过去365天每天一个可操作格子，请求次数决定颜色深浅；用于识别使用频率、活跃日期和周期，不重复表示Token消耗。
- 日期联动：点击热力图日期会选中该日，并将趋势切换到“天”显示24个小时点。
- Token构成：非缓存输入、缓存输入和输出比例继续位于折叠详情，只回答累计构成。
- 最近客户端：只回答近期用量来源，不参与时间趋势或构成编码。

## 数据边界

- `UsageDashboard`新增独立`dailyUsage`，由SQLite按本地日历日期聚合请求数、输入、缓存、输出和总Token。
- 日聚合保留两年读取窗口，热力图仅呈现最后365天；两年窗口保证用户从热力图选择任意日期后仍可切换并查看该日期所在的完整自然年。
- 新增按日期读取的`UsageHourlySummary`，使用本地自然日边界与索引范围查询，并保留输入、缓存、输出和总Token分项，不从最近请求明细推导小时分布。
- 热力图和趋势图查询均与最近50条请求明细相互独立，避免把被明细上限截断的日期误画为零使用。
- schema v9新增`usage_requests(started_at_ms DESC)`索引，为日聚合与单日分时范围查询提供稳定边界。
- 页面仍不轮询；进入页面、请求完成或用户手动刷新时读取。
