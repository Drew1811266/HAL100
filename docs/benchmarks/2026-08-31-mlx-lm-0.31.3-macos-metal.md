# MLX-LM 0.31.3 macOS Metal 真实验收

日期：2026-08-31

## 验收边界

- 原生宿主：macOS 26.5 / aarch64 / Apple Metal，Apple M1，16 GiB 统一内存。
- 引擎：官方 `mlx-lm==0.31.3`，PyPI wheel SHA-256：
  `758cfddf1180053b7613db76fad3d246a331a2a905808e1164a275621fc983b8`。
- 运行依赖：MLX `0.32.2`；运行时设备信息为 Apple M1 / `applegpu_g13g`。
- 模型：`mlx-community/Qwen3.5-2B-4bit`，固定 revision
  `674aaa7240b91e8012fcad5d791b7dfe5ba90207`。`model.safetensors` 为 1,722,271,785 字节，
  SHA-256 `713fe7e5d3c3965f7106b0d0ee17615f7869c23c8d327996df8c1196fbcf07d5`，与固定 revision
  返回的 `x-linked-size` 和 `x-linked-etag` 一致。
- 临时服务只监听 `127.0.0.1:8080`，禁用 Hub 在线访问，`HOME`、HF 与 XDG cache 全部指向系统
  临时目录；prompt/decode concurrency 均固定为4，CORS只允许回环 origin。

## 服务预检

- tokenizer 元数据确认聊天模板、工具调用解析和思考模式三项能力均存在。
- `/health` 返回 `ok`。隔离 HF cache 根不存在时，MLX-LM 0.31.3 的 `/v1/models` 会先返回 200 头、
  再因 `CacheNotFound` 在线程内失败；在同一临时环境创建空 `hub` 目录后，目录端点稳定返回唯一的
  本地模型。HAL100 适配器没有因此放宽 JSON 或模型目录合同。
- 最小工具调用返回唯一 `hal100_protocol_probe`、无思考文本并带精确 usage。系统指纹为
  `0.31.3-0.32.2-macOS-26.5-arm64-arm-64bit-applegpu_g13g`，把引擎、MLX、平台、架构和 Apple GPU
  架构绑定进部署指纹。

## 结果

- 运行产物：`acceptance-run-6a5e1d232cb644b2a7ba7db85b1b910c`，结果 `passed`。
- 精确引擎版本：`0.31.3`；协议能力哈希：
  `7d47cfab64649c9dc0b559e2bbe292294529c5e9d66095e7f0771015708a5b33`。
- 通过健康/模型目录、单一工具调用、流式响应、精确 usage、原生 Metal 支持格和运行方案
  `save/revalidate/activate/verify` 生命周期检查。
- 稳定性探针：20/20 成功、每波并发4、最大观测延迟903 ms。
- 控制面结构化韧性：取消、失败切换回滚、重启补偿三项均通过。
- 产物审阅后以固定模型 revision 导入 v1 账本；没有保存端点、用户路径、提示词、响应内容或凭据。
- 验收完成后已停止临时服务并确认8080无监听或残留进程；运行时、模型和 cache 只保留在系统临时
  目录中，没有生成或修改用户配置目录。

该结果只证明 `MLX-LM × macOS × aarch64 × Metal × local` 这一精确支持格，不是绝对吞吐基准，
也不外推到其他平台或加速器。
