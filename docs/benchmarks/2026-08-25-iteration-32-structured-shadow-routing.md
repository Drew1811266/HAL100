# 迭代32：结构化影子路由基线

- 日期：2026-08-25
- 场景合同：`contracts/agent-evals/v1-config-tasks.json` v1
- 意图合同：`contracts/agent-intent/v1-schema.json` v1
- 模型：未启动
- Sidecar：未启动
- 系统写操作：未执行
- 用户执行路径：仍使用Agent RPC v9和原关键词能力路由

## 1. 方法

Core对20个含固定提示词的场景执行`AgentTaskIntentRouter`，比较四态裁决、任务类型、外部Agent
目标和澄清类型。另用代表性固定输入确认18类工作流均可形成合法`AgentTaskSpec`，并用正反例
验证Pi意图提案schema拒绝未知目标、错误目标类型、额外解释字段和错误版本。

4个检查点恢复场景不属于文本路由，留到可恢复运行链评测。

## 2. 结果

| 指标 | 迭代31旧路由 | 迭代32影子路由 |
| --- | ---: | ---: |
| 文本场景完全匹配 | 6/20（30%） | 20/20（100%） |
| 不匹配场景 | 14 | 0 |
| 对抗场景形成任务 | 1 | 0 |
| 可达注册任务类型 | 未单独度量 | 18/18 |
| 真实模型调用 | 0 | 0 |

影子路由能够区分含糊Pi卸载、未指定Agent、多个写目标、Shell越权和删除用户配置等请求。
`AgentTaskProposalValidator`只接受注册任务和目标，Provider模式由Rust注入，提案不能携带工具、
授权、任意理由或执行参数。

## 3. 结论与限制

迭代32的L1确定性门槛已经满足，可以作为Pi结构化提案的安全前置和对照组，但这不是本地模型
自然语言智能达到100%的证据。场景集固定且规模有限，路由器也只在影子模式运行；真实Pi输出的
准确率、方差、Token、延迟、澄清质量和工具回合下降仍需后续L2/L3评测。

本次没有改变工具选择、写计划、原生确认、执行器、RPC v9、数据库schema或前端行为。
