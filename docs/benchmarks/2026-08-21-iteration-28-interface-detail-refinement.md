# 迭代28：界面细节与状态表达收口

- 日期：2026-08-21
- 版本：1.0.2 开发线
- 结论：通过

## 页面状态与任务入口

- 首页不再仅根据核心健康状态显示“全部就绪”；模型为空或推理引擎未安装时，分别给出添加模型和准备运行环境的单一推荐动作。
- 模型、推理服务、用量和操作记录的空状态都提供与当前任务直接相关的下一步，不再只说明“暂无数据”。
- 运行页在引擎缺失或没有可运行模型时显示前置条件，并隐藏当前不可执行的选择器和启动操作；停止状态不再展示强制操作。
- 推理服务先展示已配置服务，再展示高级路由；视觉、DOM、键盘和读屏顺序保持一致。
- 设置页补充应用版本、运行平台、固定关闭行为和 Agent 环境诊断入口，移除重复的外观与默认策略说明。

## 视觉细节与响应式

- Drawer 通过 Portal 挂载到 `document.body`，遮罩和面板使用完整视口高度与不透明背景；打开时锁定页面滚动并将主应用设为 `inert`。
- 软件接入摘要行使用显式网格区域，在 880 px、720 px 两档稳定保持品牌、说明、状态与动作顺序。
- 提高辅助文字和边框对比度，清理 8–10 px 的不可读正文；11 px 只用于低层级辅助信息，主要说明统一为 12 px 及以上。
- Agent 推荐任务由三列改为两列，长任务名称不再被截断；窄窗口继续使用单列。
- 页面进入动画不再对内容容器使用 transform，避免固定弹层意外建立局部包含块。

## 工程说明收口

- “不轮询”“打开页面时刷新”等实现细节不再常驻模型、服务和活动页空状态。
- 浏览器预览限制仍只在确实处于浏览器预览且涉及写操作时显示，不作为正常桌面界面噪音。
- 凭据、原生确认、一次性计划、外部源文件所有权和受管运行时边界没有变化。
