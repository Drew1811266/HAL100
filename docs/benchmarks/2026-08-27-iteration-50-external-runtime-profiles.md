# 迭代50：外部运行方案受控闭环验证

- 日期：2026-08-27
- 版本：1.0.4
- 范围：完整活动路由、schema v12/spec v2、外部Ollama方案、桌面显式重验、Pi受控计划与现实证据
- 非范围：Ollama安装/启停/升级、模型拉取或删除、Windows/Linux桌面实现、签名、公证、安装包、
  自动更新和正式升级流程

## 实现证据

- Gateway新增原子`ActiveGatewayRoute`，保留模型`hal100-active`可解析外部真实模型；SQLite在
  一个事务中保存完整活动路由和旧兼容后端字段。托管引擎测试证明临时接管后能恢复外部后端与
  解析模型。
- schema v12/spec v2严格区分托管和外部方案：托管要求SHA-256与容量合同，外部要求后端/API根、
  Ollama digest且容量为空；v11记录迁移为托管所有权。
- 桌面发现与方案管理器共享外部引擎注册表。同一引擎的多个方案目录验证只发起一次实时探测，
  不为每张卡重复访问Ollama。
- 保存、计划、确认后执行、切换后验证和Agent最终证据分别重新读取现实状态；Pi只获得所有权、
  非秘密后端ID和可选容量，不获得API根、digest或内部计划ID。
- 外部身份漂移不能直接运行；桌面“重新验证”经Rust原生确认后只更新验证锚点，不执行安装、
  启停、拉取、删除或路由切换。
- 激活结果显式区分外部所有权和可选托管运行时，避免把停止中的llama.cpp状态解释为外部失败。

## 纵向与故障测试

RuntimeProfileManager定向测试9项全部通过，覆盖：

1. 外部方案保存—实时预检—一次性激活—完整路由与数据库复验。
2. 保存后、计划前digest漂移直接拒绝，不静默更新验证身份。
3. 计划后、执行前digest漂移使授权失效且不切换路由。
4. 切换后复检失败恢复先前持久化路由。
5. 并发重复保存串行化，只留下一个数据库身份。
6. 同一外部引擎的多个方案目录复用一次探测。
7. 显式重验更新验证快照但保留最近激活时间。
8. 活动托管模型快照变化进入需要复验。
9. 托管启动/切换继续要求原生确认。

额外定向测试证明：

- 数据库重验事务更新版本/摘要/验证时间，但不伪造激活时间，并写入脱敏审计。
- Agent目录同时保留托管和外部方案，不泄露API根或digest。
- Agent外部方案计划接受未知容量并明确显示“由外部引擎决定”，仍包含Rust实时复检、回滚和
  原生确认要求。
- 外部Agent DTO只包含有界身份，不包含路径、命令、凭据或执行权限。
