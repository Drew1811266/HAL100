# 迭代1日志与窗口生命周期回归

- 日期：2026-08-17
- 机器：Apple M1，arm64
- 系统：macOS 26.5（25F71）
- 构建：Rust 1.97.1，Tauri 2.11.5，`release + benchmark-hooks`
- 测量：macOS `footprint`物理占用、`top`瞬时 CPU、进程与结构化日志检查

## 1. 日志边界

异步 JSONL写入器改为真正的按大小轮转：活动文件 `hal100.jsonl`在下一次写入将超过5 MiB前轮转，最多保留 `hal100.1.jsonl`至 `hal100.6.jsonl`六个归档。正常情况下日志目录上限约35 MiB；单条异常超大事件可能使一个文件临时超过5 MiB，因此调用方仍禁止写入流式正文和大对象。

自动化测试使用8字节阈值验证轮转顺序、旧归档淘汰和活动文件续写；macOS/Unix测试同时验证日志文件权限为 `0600`，运行时日志目录为 `0700`。实机生成的 `hal100.jsonl`也是 `-rw-------`。

新增 `RepeatedErrorAggregator`：同一稳定错误码在60秒窗口内只输出第一次，后续重复被计数；窗口结束后的下一次事件携带抑制总数，也可在已有维护时机主动排空摘要。实现只在错误到达时工作，不创建定时器或后台轮询。

## 2. 强制销毁诊断

测试 feature以 `HAL100_BENCHMARK_WINDOW_CYCLE_MODE=destroy`强制销毁和重建主 WebView。50轮中，主进程物理占用由约43.2 MiB增至约70.9 MiB；100轮测试在第15秒已达到约79.2 MiB，且 RSS仍随轮次上升。循环完成和明确退出均为0状态，退出后没有 HAL100或关联 WebKit残留进程。

该现象说明“每次关闭都销毁、每次打开都重建”不适合作为当前 macOS长期驻留策略。它是框架回收诊断结果，不代表普通隐藏/显示操作的泄漏。

## 3. 生产生命周期回归

生产路径改为拦截主窗口关闭事件、隐藏并复用同一个 WebView。测试 feature使用真实 `close → CloseRequested → prevent_close/hide → show`路径连续执行100轮，最终再次隐藏并等待3秒：

| 样本 | 物理占用 |
| --- | ---: |
| 第1秒 | 42.3 MiB |
| 第25秒 | 40.0 MiB |
| 第45秒 | 39.3 MiB |
| 第50秒，循环完成后的隐藏稳定期 | 39.4 MiB |
| 全程峰值 | 42.5 MiB |

100轮全部完成，物理占用没有随轮次增长，进程以0状态退出且无残留。测试过程只记录一次 `benchmark_window_cycles_completed`摘要，不按轮记录日志。

## 4. 关闭后空闲基准

主窗口关闭并隐藏后，`footprint`测得物理占用约41.3 MiB、峰值约42.0 MiB。`top`按1秒间隔连续6次采样：

```text
0.0%  0.3%  0.1%  0.2%  0.1%  0.0%
```

每次均不高于0.3%，内存低于80 MiB后台预算。隐藏期没有周期性“正常”日志，也没有 Agent、模型或额外 HAL100进程。

## 5. 结论

- 5 MiB × 7文件的日志磁盘边界、权限和轮转顺序已经自动化验证。
- 重复错误聚合不增加后台定时任务。
- 强制销毁模式暴露出 WebKit资源累积风险，因此只保留为诊断钩子。
- 产品采用单主 WebView隐藏复用；100轮回归无增长，空闲 CPU与物理内存均达到迭代1预算。
- 迭代1后台核心的日志与窗口生命周期性能门槛完成；1小时稳定性测试仍按路线图留在迭代9。
