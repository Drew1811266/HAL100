# 迭代25：模型与运行任务流

- 日期：2026-08-21
- 版本：1.0.2 开发线
- 结论：通过

## 实施结果

- “模型与运行”固定为模型、运行、推理服务三个子路由；模型测试不再占用独立页签，旧 `/test` 与 `/workspace/test` 会打开运行页测试抽屉。
- 模型首屏只保留本地索引清单和“添加模型”主操作。远程搜索、来源临时切换、设备建议、GGUF 导入、仓库文件选择和下载任务均进入添加抽屉。
- 默认下载源只在设置中长期保存；模型搜索时的来源切换仅影响当前任务。
- 运行页按引擎状态突出安装、启动、切换、测试或停止中的当前动作；版本、端口、路由和强制操作进入技术详情。
- 推理服务使用统一“添加推理服务”抽屉承载固定回环发现与手动配置，保存仍进入原有确认链。
- 模型下载、导入、移除、引擎安装/卸载、启动/切换和废纸篓语义均继续调用原有 Rust 计划与原生确认命令。

## 边界核对

- 外部 GGUF 仍只移除索引，不移动源文件。
- HAL100 管理模型仍在执行前复核所有权与活动状态，并只移入系统废纸篓。
- 页面收纳不构成授权；强制停止、删除和安装仍不能绕过 Rust Core。
- 所有查询仍按页面进入或明确动作触发，没有新增后台轮询。

## 验收证据

- Desktop 自动化覆盖添加模型在线/导入分支、硬件建议、统一推理服务入口和旧测试路由。
- 真实浏览器确认模型首屏只有一个主操作；添加模型和添加推理服务均可在两次交互内到达目标流程。
- 迭代总闸门：Desktop 23 项、Agent Kernel 27 项和 Rust workspace 228 项自动化全部通过；生产构建通过。
