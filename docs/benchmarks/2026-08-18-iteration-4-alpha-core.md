# 迭代4 Alpha核心闭环基准

- 日期：2026-08-18
- 机器：Apple M1，16 GiB统一内存，arm64
- 系统：macOS 26.5（25F71）
- 桌面构建：Rust 1.97.1，Tauri 2.11.5，release + benchmark-hooks，未打包
- 引擎空闲状态：未启动用户模型，没有`llama-server`进程

## 1. 纵向功能证据

- Hugging Face和ModelScope映射、公开 GGUF解析及官方服务忽略型验收通过。
- 下载模拟服务器覆盖确认后创建任务、Range断点恢复、取消、SHA-256、GGUF校验和原子索引。
- 固定 llama.cpp归档路径逃逸被拒绝；安装/卸载计划一次性消费并写入审计。
- 假`llama-server`覆盖启动、健康检查、停止、模型切换和子进程回收。
- 模型健康后 Gateway动态切换到本机引擎；真实 HTTP请求产生精确 Usage，停止后恢复原后端。
- 官方 OpenCode CLI 1.18.11在隔离临时 HOME中通过 HAL100受管配置完成 SSE调用并归属 Usage。
- Token统计页和单轮模型测试页通过浏览器语义、视觉、无模型禁用状态和控制台检查。

## 2. Gateway延迟

预热10轮、分别采样200次：

| 路径 | p95 |
| --- | ---: |
| 直接模拟后端 | 277 μs |
| 经 HAL100 Gateway | 539 μs |
| p95差值 | 262 μs |

动态后端读锁、模型测试凭据和 Usage统计没有让本机同协议转发接近5 ms预算。

## 3. 隐藏窗口后台空闲

release进程启动1.5秒后关闭并隐藏主窗口，随后采样：

- `footprint`物理占用41 MiB，峰值43 MiB。
- `ps`连续5次、每次间隔1秒的CPU样本全部为0.0%。
- RSS约121 MiB；预算继续以macOS`phys_footprint`口径判断。
- Gateway仅监听`127.0.0.1:10100`，`/healthz`返回`ok`。
- 没有`llama-server`、Agent Kernel、下载任务、目录扫描或页面轮询。
- benchmark hook明确退出状态为0；退出后端口释放，无 HAL100或 llama-server残留进程。

结果满足隐藏窗口CPU不高于0.3%、主进程物理占用不高于80 MiB的预算，并与模型管理基础版本的41 MiB保持一致。

## 4. 空闲设计复核

- 远端目录只在用户搜索时联网。
- 硬件画像、模型库、引擎状态和 Token统计只在页面打开或手动刷新时读取。
- 下载期间才启用500 ms前端进度刷新；任务终止后自动停止。
- 下载进度约每4 MiB写一次 SQLite，不按网络分块高频提交。
- Usage使用容量1024的单写入队列；统计页面不参与请求热路径。
- 托管模型只在用户显式启动时创建`llama-server`；Alpha不运行空闲卸载计时器。

## 5. 结论与保留项

迭代4 Alpha核心完成条件已满足：模型能够获取或导入、由托管 llama.cpp加载、经 Gateway被 OpenCode或测试页调用，并产生可查询的精确 Usage；安装、卸载、下载和导入均有明确确认边界。1小时稳定性、睡眠唤醒、百万 Usage、真实大模型长时间推理和故障注入仍属于迭代9，不以本次短样本替代。
