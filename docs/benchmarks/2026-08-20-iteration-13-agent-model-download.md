# 迭代13：Agent模型发现与受控下载验收

- 日期：2026-08-20
- 平台：Apple Silicon macOS开发机
- 软件：HAL100 `0.0.1-dev.0`、Agent RPC v4、SQLite schema v7
- 范围：公开模型搜索、仓库GGUF检查、一次性下载计划、Rust原生确认与既有下载管理器执行
- 非范围：签名、公证、安装包、发售、私有/gated仓库和既有下载任务管理

## 交付边界

迭代13没有建立第二套目录或下载系统。`RemoteModelCatalog`继续拥有官方来源映射和安全远端元数据，`ModelDownloadManager`继续拥有精确文件复验、可信SHA-256、空间余量、重复项、受管路径、下载状态、哈希/GGUF校验和原子安装。Agent新增三项应用能力，只负责把自然语言任务转换为“搜索→仓库检查→一次性计划”，执行仍从Rust原生确认进入同一个下载管理器。

RPC v4以有序`requiredTools`集合替代逐工具布尔字段。能力注册表、Sidecar注册顺序和共享`v4-tools.json`必须精确一致；集合最多4项、无重复、按规范顺序、包含前置闭包且最多一个写计划。Rust与Sidecar均独立验证，Sidecar筛选不是权限边界。

## 安全验收

| 条件 | 结果 |
| --- | --- |
| 来源 | 只能使用用户在HAL100数据库中选择的默认Hugging Face或ModelScope来源；模型不能自行切换 |
| 搜索结果 | 仅公开、非gated仓库，最多8项；不包含本地路径或凭据 |
| 仓库检查 | 必须精确命中同任务搜索结果；仅带可信SHA-256的GGUF，最多12项 |
| 下载计划 | 必须精确命中同任务仓库快照；管理器重新请求并绑定来源、仓库、修订、文件、大小、SHA-256、空间和目标路径 |
| 确认与执行 | 外层与底层计划均5分钟、一次性；底层ID不发送Pi；原生确认后再次检查空间、目标文件、模型索引和未完成下载 |
| 取消与替换 | 原生确认取消、新任务、任务取消或失败会废弃未使用底层计划；伪造、过期或重复消费拒绝 |
| 并发入口 | UI和Agent不能为同一目标保留两个待确认下载计划；执行时再次拒绝已存在目标或活动下载 |
| 浏览器预览 | 不运行Agent、不启动下载、不执行写操作，也不模拟成功 |
| 云端Agent | 最多接收公开目录元数据；不接收本地/目标路径、Keychain引用、客户端Key或上游API Key |

## 结论

迭代13完成。新增能力验证了迭代12的模块化单体边界：能力数量和代码量可以继续增长，但来源选择、同任务引用、一次性授权、原生确认、下载复验和事实状态所有者保持明确。后续扩展下载管理、推荐策略或更多模型来源时，应继续增加清晰能力与应用用例，不通过放宽Sidecar权限、复制下载逻辑或设置文件行数硬上限实现。
