# 2026-08-26 迭代42：显式补偿纵向验收

## 目标

验证复合图不会把“执行器成功返回”误当成真实变更，也不会在失败后自动回滚。补偿必须只针对
HAL100确实创建的状态，使用Rust固定逆操作、新的一次性计划、新的原生确认和动作后现实复验。

## 实现边界

- 正向动作执行前和执行后使用同一个`AgentTaskSuccessPredicate`与动作专属Rust读取；只有
  `Unsatisfied→Satisfied`记录`ChangedOwnedState`。
- 前态已满足、前态未知、后态证据不可用、模型回答或进程退出码均不能产生补偿资格。
- 图失败或取消不会自动调用补偿；用户只能从Agent页面显式发起下一项Rust固定逆序任务。
- 补偿节点复用现有Sidecar，但不复用正向计划、计划ID、run ID或确认；每项仍只允许一次尝试。
- 补偿完成必须来自逆操作自己的成功谓词与证据白名单；失败、取消、过期或证据不可用均故障关闭。

## 隔离执行器纵向

测试在独立临时HOME、SQLite和凭据注册表中构造两节点Rust图：

1. 为OpenCode生成配置计划并进入图节点原生确认；
2. 确认后由确定性适配器写入HAL100 Provider与独立凭据；
3. Rust接入状态复验从未满足变为满足，节点标记`changedOwnedState=true`；
4. 注入下游节点失败，图进入`failed`，没有自动文件写入；
5. 显式请求下一项补偿，Rust只返回`DisconnectExternalAgent(OpenCode)`；
6. 生成全新的断开计划并再次确认；
7. 确定性适配器只移除HAL100所有片段与凭据，断开复验满足后图进入`compensated`。

| 验收项 | 结果 |
| --- | ---: |
| 正向一次性计划/确认 | 1 / 1 |
| 逆向新计划/新确认 | 1 / 1 |
| 前后现实状态转换 | 2 / 2 |
| 自动补偿 | 0 |
| 复用旧计划或确认 | 0 |
| 最终补偿状态 | `compensated` |
| 隔离纵向测试 | 1通过 |

补偿运行时另有4项单元测试覆盖反向顺序、单活动节点、重新授权、重复补偿拒绝和脱敏检查点；
真实变更判定单元测试覆盖幂等满足、未知前态及后态证据不可用的拒绝分支。
