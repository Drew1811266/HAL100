## 协议适配结论

Qwen3.5 在 Ollama OpenAI 兼容端点上默认启用思考，原有 64 Token 资格预算因此在形成工具调用前
耗尽。Ollama 官方 OpenAI 兼容合同把 `reasoning_effort: "none"` 定义为关闭思考的请求字段；HAL100
将它建模为只允许“已禁用”的类型化资格选项，并由 Ollama 适配器同时提供给协议和稳定性探针。
这没有提高 Token 上限、放宽唯一工具调用要求，也没有向其他引擎注入 Ollama 专属语义。

资格探针完成请求后读取官方 `/api/ps`，并要求同名模型仍驻留。本次 Metal 复验观察到
`size_vram=1,395,035,994`；回环 macOS 上该非零设备驻留与原生宿主探针共同证明实际执行格为
Metal，而不是仅根据环境变量或主机具备 GPU 作推断。首次从 CPU 格直接切换标签时，Ollama 复用
仍驻留的 CPU runner，HAL100 因 `/api/ps` 中没有匹配的 Metal 模型身份而拒绝验收；显式卸载 CPU
runner 后才重新通过。这一失败没有生成或导入证据。

## 结果

- 运行产物：`acceptance-run-c3c9f2742e584ab19b613d32255bea82`，结果 `passed`。
- 精确引擎版本：`0.33.2`；协议能力哈希：
  `7d47cfab64649c9dc0b559e2bbe292294529c5e9d66095e7f0771015708a5b33`。
- 通过模型目录、单一工具调用、流式响应、精确 usage、真实宿主支持格和运行方案
  `save/revalidate/activate/verify` 生命周期检查。
- 稳定性探针：20/20 成功、每波并发 4、最大观测延迟 648 ms。
- 控制面结构化韧性：取消、失败切换回滚、重启补偿三项均通过。
- 产物人工审阅后，以实际模型 revision 导入 v1 账本；没有保存端点、用户路径、提示词、响应内容
  或凭据。
- 新资格合同复验使用临时 HOME，验收完成后已停止服务并确认没有端口或 runner 残留，也没有新建
  用户配置目录。早期首轮验收在用户目录新建的两次身份目录已完整移入废纸篓，可恢复且未覆盖既有
  目录；隔离运行时、模型注册和待审阅产物只保留在系统临时目录中。

该结果只证明 `Ollama × macOS × aarch64 × Metal × local` 这一精确支持格，不外推到 CPU、Windows
或 Linux，也不是吞吐性能基准。
