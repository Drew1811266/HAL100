# 迭代5多后端路由核心审查记录

- 日期：2026-08-18
- 环境：Apple M1、16 GiB、macOS、Rust 1.97.1、Node.js 24.18.0
- 范围：模型别名、多后端路由、请求排空、SQLite恢复、macOS Keychain和中文管理界面
- 结论：路由核心子阶段通过；迭代5故障策略与自动发现继续开发

## 已完成

- `hal100-active`选择当前活动后端；显式模型别名可为Chat Completions、Responses和Messages选择不同后端并重写实际模型ID。
- Usage保留客户端请求模型、实际模型、后端ID和协议，双后端真实回环测试证明归属不会混淆。
- 路由选择使用短时共享读锁与原子活动计数。流式响应、非流式响应和`/v1/models`都持有请求租约。
- 安全切换拒绝新请求进入排空后端，等待旧请求归零后原子替换；超时撤销排空并保持旧路由。
- 托管llama.cpp启动、停止和切换接入相同排空路径；激活失败会回收刚启动但尚未接管Gateway的进程。
- SQLite schema v7保存非敏感后端元数据、活动外部后端ID和模型别名；模型别名外键阻止删除仍被引用的后端。
- 外部后端API Key只保存到产品专用macOS Keychain。SQLite、前端状态、日志和路由快照都不包含Key。
- 重启恢复时凭据缺失会故障关闭对应后端和别名，不会降级为无认证请求。
- 中文推理后端页支持添加、编辑、设为活动、删除外部后端和管理模型别名；删除由Rust发起原生确认。

## 性能复测

使用真实回环HTTP模拟后端，预热后各采样200次：

| 路径 | p95 |
| --- | ---: |
| 直接模拟后端 | 272 μs |
| 经HAL100 Gateway | 557 μs |
| 附加延迟 | 284 μs |

附加p95继续低于5 ms预算。多后端能力没有增加后台线程、健康轮询或定时器；Keychain和SQLite只在管理操作与启动恢复时访问，不进入请求热路径。
