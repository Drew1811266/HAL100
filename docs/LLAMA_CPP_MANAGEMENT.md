# 托管 llama.cpp 开发说明

- Alpha平台：Apple Silicon macOS
- 固定上游：`ggml-org/llama.cpp`
- 固定版本：`b10218`
- 固定资产：`llama-b10218-bin-macos-arm64.tar.gz`
- 运行端口：每个会话随机选择的IPv4回环端口

## 1. 安装供应链

HAL100不执行在线脚本、Homebrew或用户 Shell。`LlamaCppManager`只下载代码中固定的官方 GitHub Release URL，要求精确资产大小和SHA-256，通过后才解包到暂存目录。

归档中的每个路径都必须是安全相对路径并保持在暂存根目录内；安装只接受固定名称的`llama-server`。代码同时固定官方归档SHA-256和解包后`llama-server` SHA-256，安装目录内的清单不能自行改变信任根。最终目录通过同父目录重命名进入权限受限的固定引擎目录；启动前重新计算完整二进制SHA-256并拒绝符号链接，安装损坏时故障关闭。

安装流程必须消费5分钟有效的一次性计划：

```text
生成计划 → 展示发布者、版本、资产大小和动作摘要
→ Rust原生确认 → 下载 → 大小/归档与二进制双SHA-256校验
→ 安全解包 → 二进制校验 → 原子安装 → 审计
```

卸载使用独立的一次性计划，先停止 HAL100托管的进程，再只删除固定引擎目录。卸载不扫描或删除模型目录，也不操作用户安装的外部 llama.cpp。

## 2. 模型运行

启动只接受 SQLite中状态为`ready`且具有完整SHA-256的模型 ID。Rust Core重新读取模型位置，拒绝符号链接和非普通文件，重新计算模型完整哈希，然后以绝对二进制路径启动固定参数：

```text
llama-server
  --model <已复核的GGUF绝对路径>
  --alias hal100-active
  --host 127.0.0.1
  --port <随机回环端口>
  --ctx-size 4096
  --parallel 1
  --reasoning off
  --api-key-file <0600临时会话Key文件>
```

标准运行时显式关闭 llama.cpp reasoning模式，保证 OpenAI兼容响应把可见答案放在`message.content`。Qwen3.5等混合推理模型在自动模式下可能先生成`reasoning_content`，当客户端给出较小输出预算时会耗尽预算并留下空正文。首版不把隐式推理模式暴露给 OpenCode或通用客户端；后续若加入思考模式，必须作为明确的模型运行配置，并同步定义 Token展示和内容兼容策略。

子进程清空继承环境、固定工作目录、关闭标准输入输出，并在最多90秒内使用独立Bearer Key验证`/v1/models`。认证就绪并复核子进程仍存活后删除临时Key文件；Key仅保留在Gateway后端配置内存中。启动失败会终止子进程并保留结构化错误码；停止、切换或桌面进程退出都会回收子进程。

启动、停止、切换和卸载由一个异步生命周期锁串行化，采用“停止当前进程 → 启动并认证检查新进程 → 在同一状态临界区更新 Gateway后端”的边界。普通停止和切换会先等待Gateway活动请求排空；用户选择独立的强制操作时，Rust原生确认后取消旧请求代次并立即恢复或接管路由。Alpha不允许两个用户模型同时常驻。

## 3. Gateway接管

Gateway把后端配置保存在共享读写锁中。模型认证就绪后，管理器把活动后端切换为本次会话的随机回环 URL并附带独立后端Key；停止托管引擎时恢复启动前的开发后端。OpenCode和内置模型测试始终使用稳定模型名`hal100-active`和 Gateway端口`10100`，不直接连接引擎端口；直接访问随机引擎端口没有会话Key会返回未授权。

因此同一次请求完整经过：

```text
OpenCode / 模型测试
→ HAL100 Gateway（客户端鉴权、请求ID）
→ 托管 llama-server
→ 后端 usage
→ UsageWriter
→ SQLite / Token统计页
```

Usage缺失时记录`unavailable`，HAL100不按字符数伪造 Token。内置测试凭据每次桌面启动随机生成，SQLite只保存其摘要；测试提示词和回答不写日志或数据库。

## 4. 空闲成本

- 未启动模型时不存在`llama-server`进程。
- 引擎状态只在打开“推理后端”页或手动刷新时检查，没有状态轮询。
- 模型测试只在用户点击发送后产生一次本机请求。
- Token统计页没有轮询；经过字段大小约束的Usage由不丢弃已接收记录的专用单写入线程异步提交到 SQLite WAL。

Alpha暂未启用15分钟自动卸载，避免后台定时唤醒和意外中断长会话；用户可显式停止模型。后续若加入空闲卸载，必须由已有请求活动时间驱动，而不是高频探测。

## 5. 已验证边界

- 安装和卸载计划不可重复消费，成功路径写审计。
- 归档路径不能逃出暂存目录。
- 假执行文件可完成随机端口启动、独立Key认证检查、未认证直连拒绝、停止和子进程回收。
- 同长度模型内容被替换后，启动前SHA-256复核失败并把模型标记为`verificationFailed`。
- 模型启动会动态接管 Gateway，请求返回后产生精确 Usage；停止恢复原后端。
- 普通模型切换/停止复用安全排空；原生确认的强制切换/停止会中断旧代请求，并将其Usage标记为`forced_route_switch`。
- 假执行文件会拒绝缺失`--reasoning off`的启动命令，防止混合推理模型重新产生空正文兼容性回归。
- 浏览器预览只展示安装计划，确认执行按钮禁用。

真实官方资产不会在自动测试中安装到用户应用数据目录。供应链升级必须重新核对官方 Release、资产大小和SHA-256，并更新固定版本测试数据。

## 6. 当前边界

- 只管理 HAL100自己的固定 llama.cpp版本，不发现或卸载系统中的其他版本。
- 只支持一个活动托管用户模型；多外部后端、模型别名、安全排空、强制切换和固定回环vLLM/Ollama连接诊断已由迭代5实现。
- 不自动更新引擎；升级必须生成新的确认计划并保留可验证版本边界。
- 当前开发版未签名、未公证，只供内部开发测试。
