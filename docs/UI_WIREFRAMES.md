## 2. 首次使用与初始化配置中心

### 2.1 首次进入

首次打开不再显示独立全屏向导，而是保留完整主导航并进入总览。未完成状态只通过总览中的轻量提醒和设置导航提示点表达，不得覆盖总览或强制跳转。

```text
│ 测试模型           │                                                         │
│ 审计记录           │  接下来做什么                                           │

│ 设置            •  │                                                         │
└────────────────────┴─────────────────────────────────────────────────────────┘
```

### 2.2 行为约束

- 基础必选项只有默认下载源和随系统登录启动选择；登录启动推荐保持关闭。
- 设备检测在打开页面时执行一次，也可手动重新检测，不进入后台轮询。
- 设置页顶部只展开两项必选偏好；设备、本地推理和软件接入只展示单行摘要及模块入口，不直接执行安装、下载或配置写入。
- 可选项失败不会阻塞应用；完成后的配置中心继续保留并显示最新状态。
- 所有高风险动作仍在对应功能页展示语义预览并进入Rust原生确认。

## 12. 设置

设置页按使用频率自上而下组织，不再增加左侧二级设置导航：

1. 初始化配置中心：基础偏好、环境、本地推理和软件接入状态。
2. 外观与窗口行为：主题与固定的后台驻留规则。
3. Token与数据：保留周期、清理预览和显式清理。
4. 后续扩展：模型存储、云端Provider和日志等继续使用同层卡片。

基础偏好按项保存。首次未完成时，登录启动选择会和下载源一起在“完成基础设置”时提交；完成后可在原位置直接切换。数据清除、凭据撤销和恢复OpenCode备份仍进入确认流程。

## 16. 下一轮线框评审重点

1. 一级导航是否符合用户理解顺序。
2. 总览是否优先展示了最重要状态。
3. “模型库”和“推理后端”的边界是否清楚。
4. “应用接入”是否需要把客户端凭据独立成子页面。
5. Agent工具卡、确认面板与普通对话的层级是否清楚。
6. Token统计首屏指标是否过多或不足。
7. 设置分组是否符合实际使用频率。
8. 全局任务中心是否足以承载下载和安装，不需要单独导航。
