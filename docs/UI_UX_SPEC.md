## 1. 设计定位

HAL100不是聊天产品，也不是面向工程师的传统控制台。它应当呈现为一个安静、可信、易理解的本地 AI控制中心。

视觉关键词：

- 安静
- 温暖
- 克制
- 可信
- 清晰
- 专业
- 本地感

界面借鉴 Claude Desktop的留白、柔和表面、圆角、简洁侧边导航和对话体验，但 HAL100使用自己的暗红品牌色、系统管理信息架构和受控操作语言。Claude Desktop当前以统一桌面应用承载多个工作区；HAL100只借鉴这种统一工作台结构，不复制其产品分区。

参考资料：

- [Claude Desktop官方下载页](https://claude.com/download)
- [Claude Desktop官方快速入门](https://code.claude.com/docs/en/desktop-quickstart)

## 2. 设计原则

### 2.1 先说明状态，再提供操作

用户进入任何页面时，首先看到当前状态、是否健康、正在发生什么以及是否需要处理。主要操作不应遮挡状态。

### 2.2 一个区域只有一个主要动作

同一卡片、对话框或空状态最多设置一个高强调主按钮。其他操作使用次级按钮、文字按钮或更多菜单。

### 2.3 危险操作不伪装成普通动作

安装、卸载、删除和强制切换统一展示目标、来源、大小、路径摘要、影响、可恢复性和确认按钮。颜色不是唯一风险提示。

### 2.4 Agent过程可观察

HAL100 Agent不能只显示“正在思考”。硬件检测、计划、工具请求、等待确认、执行进度和结果必须以结构化卡片呈现。

### 2.5 专业页面可以密集，但不能拥挤

所有页面首屏都保持克制，只直接呈现当前状态、下一步动作和需要处理的异常。模型、后端、统计和审计页面可以承载更多信息，但技术参数、次要说明和高级配置必须通过折叠区、筛选或详情面板按需显示。

### 2.6 不依赖隐藏知识

不要求用户理解 GGUF、量化、上下文长度、OpenAI协议或 KV Cache。专业术语保留，但首次出现时提供简短解释。

### 2.7 后台状态始终可找到

首页负责汇总当前最高优先级状态；模型运行、活动请求和受控操作分别在“模型与运行”“活动”中拥有稳定入口。为减少常驻噪音，不在所有页面重复显示端口、内部进程或无异常的技术状态。

## 3. 应用窗口与布局

### 3.1 窗口

| 项目 | 规范 |
| --- | --- |
| 高保真基准画布 | 1440 × 900 px |
| 建议首次打开大小 | 1280 × 800 px |
| 最小窗口 | 880 × 620 px，已完成真实中文内容校准；复杂页面在此宽度自动降为单列 |
| 最大窗口 | 跟随桌面可用区域 |
| 标题栏 | macOS Overlay融合标题栏，隐藏文字标题，保留并校准原生红黄绿窗口按钮 |
| 窗口关闭 | 隐藏并复用主 WebView，Rust Core继续运行；隐藏态暂停全部周期活动 |
| 恢复 | 记住上次非全屏窗口尺寸和位置，越界时回到可见区域 |

首版不设计移动端、窄屏折叠导航或触摸布局。

### 3.2 应用骨架

```text
┌──────────────────────────────────────────────────────────────┐
│ macOS标题栏 / 可拖拽区                                      │
├───────────────┬──────────────────────────────────────────────┤
│ 左侧导航      │ 页面标题与页面级操作                         │
│ 228 px        ├──────────────────────────────────────────────┤
│               │                                              │
│               │ 主内容区                                     │
│               │                                              │
│               │                                              │
│ 设置          │                                              │
└───────────────┴──────────────────────────────────────────────┘
```

- 左侧导航固定宽度228 px，不允许用户拖动。
- 页面顶部区域高度64 px，包含标题、说明和最多两个页面级操作。
- 主内容区默认水平边距32 px，窗口较小时降为24 px。
- 列表和表格页面占满可用宽度；阅读和 Agent内容最大宽度820 px并居中。
- 右侧详情使用360–420 px抽屉，不频繁打开新窗口。

### 3.3 全局状态入口

- 首页只显示一份用户可读状态、一个最高优先级推荐动作和必要的常用入口。
- 一级导航固定提供“模型与运行”“软件接入”“Agent”“活动”；设置独立位于侧栏底部。
- Gateway端口、内部ID和无异常的进程状态只在用户主动展开技术详情时显示。
- 下载、执行和确认中的任务在其所属页面持续可见；当前版本不建立独立的全局任务中心。

## 4. 信息架构

### 4.1 一级导航

| 顺序 | 导航 | 主要目的 |
| --- | --- | --- |
| 1 | 首页 | 查看当前唯一优先事项、真实就绪状态和下一步建议 |
| 2 | 模型与运行 | 通过稳定子页管理模型、托管运行时和外部推理服务 |
| 3 | 软件接入 | 管理 OpenCode、Pi、OpenClaw、Hermes 与通用客户端 |
| 4 | Agent | 诊断、部署检查并生成受控操作计划 |
| 5 | 活动 | 通过独立子页查看精确用量和受控操作记录 |
| - | 设置 | 独立位于侧栏底部，管理基础偏好、外观、数据策略和关于信息 |

导航不提供简单模式和高级模式。页面根据内容逐步披露细节，但不隐藏真实状态。

### 4.2 全局入口

- 模型测试：并入“模型与运行”的运行任务，以抽屉承载单轮验证。
- 用量与操作记录：共用“活动”页面外壳，但查询、数据和保留策略保持独立。
- 设置：固定在侧栏底部，不重复提供外观或任务入口。
- 命令搜索：首版不提供，避免扩大范围。
- 帮助：设置页中的文档与问题反馈入口。
- 托盘：独立于主窗口，提供最小高频操作。

### 4.3 导航状态

- 当前页面：暖色低对比背景、清晰文字、左侧2 px品牌标记。
- Hover：仅改变背景，不移动图标或文字。
- 有问题：导航右侧显示小型语义状态点或数量，不使用跳动动画。
- 导航标签固定为中文，不因窗口宽度变成缩写。

## 5. 品牌与主题

### 5.1 品牌表达

- 名称始终写作 `HAL100`。
- Logo使用原创的简约摄像头机器人图形：单镜头表示检测与观察，小型底座表示本机受控 Agent；不再使用临时“H”字标。
- 图形使用暖砖红和暖米白两色，在16–48 px小尺寸中保持单一清晰轮廓，不加入文字、渐变、3D或高频细节。

## 6. 字体、间距与形状

### 6.1 字体

```css
--font-ui: -apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI",
  "PingFang SC", "Microsoft YaHei UI", "Microsoft YaHei", sans-serif;
--font-display: -apple-system, BlinkMacSystemFont, "SF Pro Display",
  "Segoe UI Variable Display", "Segoe UI", "PingFang SC",
  "Microsoft YaHei UI", "Microsoft YaHei", sans-serif;
```

| 样式 | 字号/行高 | 字重 |
| --- | --- | --- |
| 欢迎标题 | 28/36 | 600 |
| 页面标题 | 27–32/1.24 | 650 |
| 区块标题 | 16/24 | 600 |
| 正文 | 14/21 | 400 |
| 紧凑正文 | 13/19 | 400 |
| 辅助文字 | 12/18 | 400 |
| 指标数字 | 20–40/1.2 | 650，使用等宽数字特性 |
| 代码/地址 | 12/18 | SF Mono或系统等宽字体 |

中文正文避免使用过细字重。界面标题、指标和正文统一使用系统无衬线字体，不混用Georgia、宋体或其他装饰性衬线字体。Token、端口、速度、文件大小和时间使用等宽数字特性对齐；代码、地址和模型ID才使用等宽字族。

### 6.2 间距

- 基础单位：4 px。
- 常用间距：8、12、16、20、24、32、40 px。
- 卡片内边距：20或24 px。
- 表格行高：44 px；紧凑审计表可为40 px。
- 表单字段垂直间距：16 px。

### 6.3 圆角与边框

- 输入框和按钮：10 px。
- 卡片：14 px。
- 大型对话框和确认面板：16 px。
- 标签与状态胶囊：999 px。
- 默认边框：1 px。
- 阴影仅用于浮层和抽屉，普通卡片不依赖阴影分层。

## 7. 核心组件

### 7.1 按钮

- Primary：品牌暗红实底，每个区域最多一个。
- Secondary：表面色加边框。
- Ghost：无边框，用于低风险辅助操作。
- Destructive：危险红，仅出现在明确风险上下文。
- Icon Button：必须有 Tooltip和辅助功能名称。

按钮状态覆盖默认、Hover、Pressed、Focus、Disabled和Loading。Loading按钮保持宽度不变。

### 7.2 状态标记

统一状态语言：

- 健康
- 未运行
- 正在启动
- 正在停止
- 下载中
- 等待确认
- 已暂停
- 已完成
- 警告
- 失败
- 外部管理

状态组件由图标/形状、文字和颜色共同表达。

### 7.3 卡片

- Summary Card：单个关键指标和趋势。
- Entity Card：模型、后端或客户端摘要。
- Recommendation Card：建议、原因和一个主要动作。
- Tool Run Card：Agent工具的参数、风险、进度和结果。
- Warning Card：需要注意但不会立即阻断流程。

卡片不能层层嵌套超过两级。

### 7.4 列表与表格

- 默认左对齐文字、右对齐数字。
- 列表行点击打开详情抽屉；行内按钮只保留一个高频动作和更多菜单。
- 表头在长列表滚动时保持可见。
- 筛选条件以可移除标签显示。
- 空结果必须区分“没有数据”和“筛选后没有结果”。

### 7.5 表单

- Label始终可见，不使用 Placeholder代替 Label。
- Base URL、路径和 Key使用等宽字体。
- API Key输入后只显示存在状态和尾部提示。
- 校验错误紧邻字段，并提供修复方法。
- 修改 OpenCode配置前必须显示差异预览。

### 7.6 对话框与抽屉

- 普通详情使用右侧抽屉。
- 简短确认使用居中 Dialog。
- 多字段创建流程使用 Sheet或页面内步骤，不使用窄小弹窗。
- 对话框打开后保持键盘焦点，Escape只关闭不会导致数据丢失的弹层。

### 7.7 所属页面任务状态

- 下载、校验、安装、启动和清理任务在其所属页面持续显示状态与进度。
- 当前阶段、速度、剩余时间和目标只在任务存在时出现，不建立常驻全局任务中心。
- 暂停、继续、取消、重试和查看详情与对应任务保持同一上下文。
- 离开页面不终止后台任务；重新进入时通过按需查询恢复当前状态。

## 8. 风险与确认体验

### 8.1 风险等级表达

| 风险 | 表现 |
| --- | --- |
| 只读 | 普通工具卡，无确认 |
| 可逆 | 说明影响，必要时普通确认 |
| 安装 | 展示来源、版本、大小、路径和许可证，确认后执行 |
| 破坏性 | 危险标题、影响列表、可恢复性、二次确认 |
| 禁止 | 不显示执行入口，解释为什么不可用 |

### 8.2 统一确认面板

确认面板必须包含：

1. 动作标题。
2. 目标名称和类型。
3. 参数摘要。
4. 会发生什么。
5. 是否影响活动请求。
6. 是否可恢复。
7. 取消和明确动作按钮。

不得使用模糊按钮文字，如“好的”“继续”。按钮应写明“安装引擎”“移到废纸篓”“强制切换并中断请求”。

### 8.3 Agent确认

Agent消息只能引出确认面板，不能把用户在聊天中输入“可以”直接视为系统授权。确认按钮由 Rust Core生成和处理。

## 9. HAL100 Agent交互

### 9.1 页面结构

- 顶部：Agent边界折叠说明、Pi Core、本地模型、后台策略和按需环境诊断。
- 主工作区：左侧为单任务编辑器，右侧为工具轨迹、受控计划和最终回答；宽窗口采用非对称双栏，右侧结果区略宽。
- 编辑器：推理范围使用紧凑分段选择，当前范围的隐私说明只显示一条；任务输入和字数紧邻，避免状态信息与输入割裂。
- 快捷任务：首屏只展示四个常用入口；Gateway、模型切换、引擎安装和OpenCode计划放入“更多计划模板”，展开后仍只填入任务，不直接执行。
- 操作区：安全说明与运行控制形成独立页脚；停止运行时、取消任务和主要执行动作保持层级差异。
- 结果区：顶部固定显示“理解任务—调用工具—生成回答”三阶段，空状态置于轻量边界容器内；真实工具轨迹出现后才进入完成态。
- 窗口宽度低于1100 px时工作区降为单列，避免Provider名称和计划入口被截断。

迭代8在同一标准页面中提供“本地Qwen”“云端单次增强”和“当前会话使用云端”三个明确范围，本地仍默认选中。云端区域只列出已启用、已载入且已配置凭据的OpenAI/Anthropic兼容后端，并要求用户输入模型ID；无可用后端时只提供前往“推理后端”配置的链接。单次模式第一次提交只生成本次发送预览，显示后端、模型、任务字节数、系统指令/工具结果范围，以及“凭据与本地路径不发送”；用户点击预览中的明确按钮后仍需通过Rust原生确认。当前会话模式先生成范围预览，明确后续任务会发送、工具结果可能发送、聊天历史不保存以及退出/重启即失效；通过Rust原生确认后，页面固定显示后端、模型、健康或故障状态与“退出云端会话”按钮，其他Provider选项暂时锁定。浏览器预览明确禁用本地与云端执行，不生成模拟答案。

### 9.2 空状态

只显示 HAL100领域建议：

- 检测这台 Mac适合运行什么模型。
- 检查为什么本地模型无法启动。
- 帮我安装托管 llama.cpp。
- 帮我配置 OpenCode连接 HAL100。

不显示写作、翻译、搜索、编程等通用聊天建议。

### 9.3 Tool Run Card状态

```text
已计划 → 等待确认 → 执行中 → 已完成
                    ├→ 用户拒绝
                    ├→ 已取消
                    └→ 失败/可重试
```

卡片始终显示工具的用户可读名称，不直接以内部函数名作为主标题。内部工具名只在详情中显示。

### 9.4 云端模式

- 云端模式使用持续可见但不刺眼的状态条。
- 首次发送前打开脱敏预览。
- 明确显示“仅本次”或“当前会话”。
- 禁止本地失败后静默出现云端内容。
- “仅本次”逐次生成范围预览并确认；“当前会话”经一次范围确认后只在当前内存会话有效，退出或重启立即失效。

## 10. 页面级设计摘要

| 页面 | 主视图 | 详情方式 | 主要动作 |
| --- | --- | --- | --- |
| 首页（含首次设置提醒） | 当前真实就绪状态与一个推荐动作 | 技术详情按需展开，任务跳转所属模块 | 处理当前唯一优先事项 |
| 模型库 | 本机模型列表与空状态 | 添加模型抽屉 | 添加模型 |
| 运行 | 托管引擎状态与当前可执行动作 | 技术详情与模型测试抽屉 | 安装、启动或停止 |
| 推理服务 | 已配置服务优先，高级路由随后 | 添加服务抽屉与折叠管理 | 添加推理服务 |
| 软件接入 | 五类客户端统一摘要行 | 每客户端独立详情抽屉 | 当前推荐接入动作 |
| 活动·用量 | 主指标、年/月/周/天 Token 趋势、全年活跃度与最近客户端 | 构成与请求明细按需展开 | 选择日期、测试当前模型或刷新 |
| 活动·操作记录 | 精简操作列表 | 筛选折叠与详情抽屉 | 刷新 |
| HAL100 Agent | 单任务编辑器、推荐任务与结果 | 工具轨迹和技术ID按需展开 | 运行受控任务 |
| 设置 | 基础偏好、外观、数据策略与关于 | 页面内分组 | 保存当前设置 |

## 11. 加载、空状态与错误

每个页面必须设计：

- 首次加载 Skeleton。
- 无数据空状态。
- 筛选无结果。
- 局部请求失败。
- 整页不可用。
- 权限或配置不足。
- 后台进程崩溃。
- 断网但本地功能可用。

局部失败不应替换整个页面。Gateway可用但某个外部后端失败时，其余内容继续工作。

错误文案结构：发生了什么、影响什么、用户现在能做什么。技术错误码放在可展开详情中。

## 12. 动效与反馈

- 页面切换：120–160 ms淡入，不做大幅位移。
- 抽屉和对话框：160–200 ms。
- 状态点呼吸：只在启动、停止或执行中使用，周期不短于1.6秒。
- 下载和安装进度使用真实进度；未知时使用不确定状态，不伪造百分比。
- 成功操作使用轻量状态变化，不弹出阻断式庆祝动画。
- 支持系统“减少动态效果”设置。

## 13. 可访问性与键盘

- 正文和关键控件满足 WCAG AA对比度目标。
- 键盘焦点清晰可见。
- 所有核心流程可仅用键盘完成。
- 表格支持方向键或标准 Tab顺序，不制造焦点陷阱。
- 图标按钮具有可访问名称和 Tooltip。
- 状态不能只使用红/绿区分。
- 支持 macOS系统字体缩放后的合理布局。
- 对话框打开时焦点进入；关闭后返回触发元素。
- 首版快捷键：`⌘,` 打开设置，`⌘W` 关闭窗口，`⌘K` 暂不占用。

## 14. 托盘界面

托盘菜单遵循 macOS原生菜单样式，不套用主窗口卡片视觉。顺序：

1. 打开 HAL100。
2. Gateway状态与端口，只读。
3. 当前活动模型。
4. 启动/停止当前托管模型。
5. 切换到已配置模型子菜单。
6. 活动请求数。
7. 下载任务暂停/恢复，仅有任务时显示。
8. 设置。
9. 退出 HAL100。

危险操作仍需要打开主窗口完成确认，不在原生托盘菜单中进行复杂二次确认。
